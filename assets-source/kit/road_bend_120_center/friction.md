# road_bend_120_center friction

1. **The centre/edge joint gate assumed a straight piece** (about 15 min). `kit_gate::check_center_edge_joint` took the sections at runtime x = +6 and x = -6 of every `kind: center` piece, so any turning piece failed with "no vertices on x = +-6". Fix: the check reads each centre piece's lane edges from the tile that names it (`hex_core::TileCatalog::builtin()`), rotates the piece so each lane lands on edge 0 and compares the section at x = 6 with the edge piece's, within one 0.1 mm unit to absorb the f32 rotation. For lanes 0 and 3 this is the old check. Skill: `gates.md` (Seam: lanes) and `pitfalls.md` (Turning road pieces).
2. **The `_road.py` bend dash rule cannot be applied literally** (about 10 min). It spaces dashes over the edge-to-edge path at period L / n, but the `road_straight_edge` stubs are frozen at period P with a dash crossing the joint. Reading used: each end of the centre path continues the stub's dash for 1.843 m, and the free span between holds m dashes and m + 1 gaps of equal length (`_road_bend.dash_intervals`). `_road.py` stays byte-identical (it is hashed into the approved straights), so the reading is documented in `_road_bend.py`. Skill: `pitfalls.md` (Turning road pieces).
3. **Tile network points described the wrong path** (about 5 min). `data/tiles/road_bend_120.ron` gave a 24 m arc between edge midpoints, which the stubs (straight to r = 6) cannot follow. Updated to the two joints plus the midpoint of the real 10.392 m arc. No skill change: tile data, not the pipeline.
4. **The worktree hook refused a `cat > file <<EOF` heredoc** for a scratch shot script (1 min). Wrote it with the Write tool. Already covered by SKILL.md (Worktree sessions); no change.
