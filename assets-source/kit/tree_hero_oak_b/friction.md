# tree_hero_oak_b friction log

Snags hit while building the hero oak's forked variant (scripted route, headless). Each entry: what happened, the fix, minutes lost, and the proposed skill text (sibling agents run in parallel, so the orchestrator folds it in).

1. **The 1.2x normal-preservation assert tripped at 2e-4.** `tree_hero_oak.py` asserts every custom corner normal survives `normals_split_custom_set` after the uniform scale within 1e-4. On this crown five canopy corners (faces of about 0.05-0.08 m²) came back 2e-4 off. That is the precision of Blender's compressed custom-normal storage, not a geometry change, and it is far below anything visible. Fix: `_oak_fork.py` prints the moved corners' slots and areas and asserts at 1e-3. Lost: about 4 min. Proposed `pitfalls.md` line (Leaves, foliage and LODs, after "Scaling a baked piece up"): "Re-set custom normals round-trip through Blender's compressed corner-normal space, so after a scale a few corners can come back 1e-4 to 2e-4 off. Assert at 1e-3, and print which slot moved, so the check still catches a real flip."
2. **Default `seed=` arguments are bound at definition time.** `_tree.layout`, `_oak.canopy_high` and `_oak.leaf_cards` take `seed: str = SEED`, which Python binds when the module is imported. Setting `_tree.SEED` / `_oak.SEED` from a family file changes `hash01` and `lump_terms`, which read the global at call time, but not those defaults. Fix: pass every seed explicitly: the hero's to `canopy_high` and `_leaves.strip` so the look matches, and the piece id to `leaf_cards`. Lost: 0 min (caught on reading, advisor). Proposed `SKILL.md` Helpers sentence, appended to "set its module globals from the new family file at import time": "Module globals do not reach default arguments, which are bound at import time (`seed: str = SEED`), so pass those explicitly."
3. **The first form was not different enough at play distance.** A leaning trunk, a fork and a south shelf with the lobes 4-5 m apart still read as one round dome from the front: the low shelf filled the notch. Lobe tops pulled apart (x +2.8 and -3.0, the east lobe 2.2 m higher) and a stronger lean (1.2 m at 3.7 m) gave a V crown in front view and a split crown from above. Comparing the hero, the variant and both scatter oaks in a 4 x 4 grid of the six-view renders on skip-bake GLBs settled it in two builds, before any bake. Lost: about 5 min. No skill change: the skill already says to judge pieces from stills before baking.
4. **The perch table needs the GLB, and the Rust test is slow to iterate on.** `oak_perches_sit_on_the_canopy` checks perches against the shipped LOD0 shell and leaves (foliage top within -0.02..+0.08 m in a 0.35 m disc, a shell vertex within 0.6 m, nothing more than 0.35 m above within 0.8 m). A 60-line Python solver (a Blender dump of the staged GLB's LOD0 foliage triangles plus a numpy port of the same checks, a greedy pick of 12 perches at least 0.8 m apart with lifts under 0.2 m) found the 12 perches in one pass. The Rust test passed first time with them. Lost: 0 min. Proposed `project.md` "Fast loops" line: "A tree that roosts birds needs a perch table checked against its shipped LOD0: dump the staged GLB's canopy and leaf triangles and solve the perches with the same checks before writing the Rust table (`docs/checkpoints/tree_hero_oak_b/` integration, 2026-10-20)."
5. **The glTF importer renames TEXCOORD_1.** A Blender still that colours by the `wind` UV map rendered black: the reimported GLB names its layers `UVMap` and `UVMap.001`. Fix: take the second UV layer by index. Lost: about 3 min. Proposed `pitfalls.md` line (Coordinate frame and export): "A reimported GLB names TEXCOORD_1 `UVMap.001`, not `wind`. Debug renders take it by index."
6. **The worktree hook refuses a shell loop over a variable** (`for n in …; do ffmpeg … $n …`), even with only literal names. Fix: put the loop in a script file and run it as one plain command. No skill change: `SKILL.md` "Worktree sessions" already says this.
7. **The top and play frames looked offset from the oak, but the camera was where the script put it.** A `dump_state` after the top shot reads `camera.pos` (-27.7, 75, 0.1), exactly the scripted pose. The oak only sits off the frame centre because a hex at q = -1, r = 0 is at x -27.7, and the variant's crown is lopsided east of its trunk. Waits after each camera move were raised from 10 to 120 frames anyway. No skill change. Lost: about 3 min.
8. **The first walk-into-the-trunk dump showed no block.** `walk_to` (-27.7, 6) and a 3 s `walk_step` stopped 3.2 m short of the 2.45 m collider. A 7 s step with a 450-frame wait (as the farm checkpoint does) gives `blocked: "tree"`, `blocked_by: "tree_hero_oak_b"`. No skill change. Lost: about 2 min.
