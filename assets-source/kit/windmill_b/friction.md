# windmill_b friction log

1. **The original generator cannot be imported and has no family helper.** `windmill.py` builds at import (`main()` at module level) and keeps its bmesh accumulator, lathe and bake sequence inline, so a variant cannot reuse them through module globals. Fix: copied the accumulator and the bake sequence into `windmill_b.py` (the documented "monolithic steps" route, `pitfalls.md` Variants), and took `fill_unbaked` and `centroid_samples` from `_house.py` (now its one `generatorDep`). Minutes lost: 3. Skill: no change (the route is documented). A later windmill variant would want a `_windmill.py` helper; moving `windmill.py`'s code there would stale `windmill`, so leave it until `windmill` is rebuilt for another reason.
2. **`project.md` says play cannot draw rotors.** "Rotors" ends with "`play.rs` loads only `<id>_lod<n>`, so a rotor piece placed in play needs that path extended first". It is stale: `play.rs` `build_piece` loads `rotor_mesh_name(id, lod)` for any id and `spawn_kit_parts` parents it under its LOD body with a `KitRotor`, so a variant whose nodes are `windmill_b_rotor_lod{0,1,2}` turns with no runtime change. Fix: none here (one-writer rule). Proposed skill text below. Minutes lost: 2.
3. **The default sharp angle smoothed the octagons.** `windmill.py`'s `SHARP_DEG = 50` is above an octagon's 45° corner turn, so the smock and the brick base shaded round in the first six-view render and lost the smock-mill read. Fix: `SHARP_DEG = 40` (the 12-gon cap's 30° steps stay smooth). Minutes lost: 3. Skill: proposed pitfall below.
4. **A flat annulus has no reliable "outward" for the lathe's normal check.** The accumulator orients a lathe band by its horizontal radial vector, which is perpendicular to a horizontal ring's normal, so a weatherboard lap built as a flat step would flip at random. Fix: each lap rises EPS = 2 cm across its LAP = 4.5 cm step, so its normal keeps an outward part; the stage deck's rings are built as explicit faces with up and down normals. Minutes lost: 0 (caught before the build). Skill: no change (local to the copied accumulator).

5. **`git apply --3way` stages what it applies.** Re-verifying the integration patch after a rebase, `git apply --3way` wrote the crate edits into the index too, so `git checkout -- crates` (which restores from the index) left them in place and the next `git diff --output=… -- crates` wrote an empty patch. Fix: `git diff --cached --output=…` while staged, then `git restore --staged --worktree crates`, and `git apply --check` the result against HEAD. Minutes lost: 3. Skill: proposed text below.
6. **The first kit cell hid the variant behind the original.** (4, -2) lies exactly along the line the windmill's sails face at yaw 120 (-0.5, 0.866), so every front view of one mill looked through the other. Fix: (4, -1), east of the windmill. Minutes lost: 6 (one release rebuild and shot run). Skill: no change (layout-specific).

## Proposed skill text (for the orchestrator)
- `references/dispatch.md` or SKILL.md, integration patches: "`git apply --3way` updates the index. After a trial apply, regenerate with `git diff --cached --output=<patch> -- crates` and reset with `git restore --staged --worktree crates`; plain `git checkout -- crates` keeps the staged edits."
- `project.md`, Rotors: replace the last sentence with "Play draws rotors too: `play.rs` `build_piece` loads `<id>_rotor_lod<n>` for any piece and spawns it under its LOD body with a `KitRotor` (`spawn_kit_parts`), so a variant that keeps the node names and the local-X contract turns with no runtime change (`windmill_b`, 2026-10-20). Sweep the rotor through a full turn in the generator and assert it clears the body and stays above walker height (`windmill_b.sail_clearance`)."
- `pitfalls.md`, Blender and its API: "**Sharp-angle threshold against faceted bodies.** `set_sharp_from_angle` with 50° smooths an octagon (45° corners) into a cylinder; keep the threshold below the facet turn you want to read (`windmill_b`: 40°)."
