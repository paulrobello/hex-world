# train_engine / train_carriage friction (2026-10-19)

1. **Hull collider over a vehicle LOD2 carries zero tangents.** `collider_from(lods[2], "hull", ...)` kept LOD2's atlas UVs, which collapse on some hull faces; `export_glb` failed on `train_*_collider TANGENT not unit` (carriage first, then the engine after the first fix). Fix in `_train.py`: a `box` collider with an oblique planar UV, flat shaded. About 6 minutes. Proposed pitfall text (Coordinate frame and export): "A collider built from a LOD keeps that LOD's atlas UVs, which degenerate on hull or box faces and fail `export_glb` with zero tangents: give the collider its own oblique planar UV (`_train.py`)."
2. **Second import of one GLB in a Blender still gets `.001` names.** The rail still's `place()` deletes every mesh not named exactly `<id>_lod0`, so a second carriage lost its LOD0 and `next()` failed. Fix: compare `name.split(".")[0]`. 3 minutes. No skill change: the still scripts are per checkpoint.
3. **Kit-scenario shots cannot show runtime paint.** `kit_scene` draws through `KitMaterial`, which has no MeshTag paint input, so a car-style piece shows white in the kit scenario; runtime colours are shown in EEVEE with `car_material.wesl`'s formula. Proposed skill text (project.md, Budgets, after the cars): "Runtime-painted pieces (cars, the train) render unpainted in `--scenario kit`; show the runtime colours in the EEVEE stills (`docs/checkpoints/train/still.py`) or in play."
4. **The `car_*` paint-mask gate does not cover the train.** `kit_gate::paint_mask_errors` runs only for ids starting with `car_`. The generator asserts a painted face per LOD; the orchestrator should extend the gate's condition to `train_` (one line in `kit_gate.rs`, `p.id.starts_with("car_") || p.id.starts_with("train_")`).
5. Host load was 244 at start; the brief's bootstrap waited for main's wasm build (about 55 minutes lost before modeling).
