# tree_hero_oak_c friction log

Snags hit while building the hero oak's third, stag-headed variant (scripted route, headless). Each entry: what happened, the fix, minutes lost, and the proposed skill text (sibling agents run in parallel, so the orchestrator folds it in).

1. **The variant caps live in the shipped GLB, and nothing outside Rust measured them.** `hero_variants_fit_inside_the_authored_piece` needs the variant's collider reach and crown reach (max over LODs) under the hero's, and Q49 needs its height under the hero's. The brief's 13.3 m / 8.5 m are rounded, and `_oak_fork` prints height on LOD0 only, while the LOD1/LOD2 card subsets are scaled up about their centres and can sit higher (here LOD2 is the highest LOD at 12.557 m and the widest at 8.225 m). Fix: `docs/checkpoints/tree_hero_oak_c/measure.mjs` reads a staged or meshopt-compressed GLB through the pinned gltf-transform and MeshoptDecoder and prints per-mesh height, depth, reach and tris (hero: 13.294 m, 8.471 m, collider 2.448 m), and dumps LOD0 foliage and bark triangles for the perch solver. Lost: about 3 min. Proposed `project.md` "Fast loops" line: "Measure a variant's caps from the hero's shipped GLB, max over every LOD and the collider (`node docs/checkpoints/tree_hero_oak_c/measure.mjs <glb>`), before choosing its clumps."
2. **Extending a pending sibling's builder without copying it.** `_oak_fork.build` looks up `layout` and `skeleton` as module globals at call time, so `_oak_ancient.py` wraps the saved original `skeleton` (strands, roots, limbs and secondaries unchanged), appends the bare dead limbs, renumbers ids, and restores the global in a `finally`. `_oak_fork.layout` raises KeyError on any feed other than leader_a, leader_b, limb, heavy and sec, so the dead wood is not a clump feed at all. Lost: 0 min (advisor, before writing). Proposed `SKILL.md` Helpers sentence, after "set its module globals from the new family file at import time": "To add parts to a sibling builder's skeleton, wrap its module-global function (keep the original, call it, append, renumber, restore it in `finally`) and assert the invariants the builder relies on (here `skel[:3]` are the strands, no level 3)."
3. **The skip-bake GLB is the shipped GLB.** `_oak_fork.build`'s skip-bake path changes only the maps, and `make kit-determinism` (a skip-bake double run) gave the same SHA-256 as the full GPU-bake build (c8819121...). So the perches, the footprint rows and the Rust tests were all settled on the skip-bake GLB while the bake ran, with no rework. No skill change: `project.md` already says to iterate with `HEXW_SKIP_BAKE=1`; this confirms it holds for the hero-oak family.
4. **A perch under dead wood passes the Rust perch test.** `oak_perches_sit_on_the_canopy` reads only the canopy and leaf triangles, so a perch under a bare dead limb would pass and look wrong. Fix: `docs/checkpoints/tree_hero_oak_c/perches.py` (the b friction entry 4 recipe, now committed: clumps from the bake report, the Rust checks ported to numpy, plus no bark vertex above a perch within 0.8 m, perches 0.8 m apart, round-robin over clumps) found 12 perches on all seven domes in one pass, and the Rust test passed first time. Lost: 0 min. Proposed `project.md` "Fast loops" line: "Solve a roosting tree's perch table with `docs/checkpoints/tree_hero_oak_c/perches.py <piece> <tris.json> 12` on the staged GLB before writing the Rust rows; it also keeps perches out from under bark."
5. **A one-line no-op heredoc was refused by the worktree hook.** My own slip (`python3 - <<'EOF'`); `SKILL.md` "Worktree sessions" already forbids it. No skill change. Lost: 1 min.
6. **Host load 170-250 during the whole run.** The full build baked on the GPU (`HEXW_BAKE_DEVICE=GPU`) and finished in a few minutes; the CPU default would have competed with the load. No timing was measured. No skill change: `lib.bake.setup_cycles` already reads `HEXW_BAKE_DEVICE`.
