# Hex World music: owner workflow

The music is generated by the owner in Suno (PRD D13, §8.2) and mastered by repo scripts. The prompts live in [`prompts/`](prompts/README.md), one file per cue. The P2 slice needs `meadow-day`, `coast-breeze` and `hearth-town`.

## Steps

1. **Generate in Suno.** Open the cue's prompt file, for example [`prompts/meadow-day.md`](prompts/meadow-day.md). Turn Instrumental on, then paste the Style, Exclude and Lyrics/structure blocks into Suno's matching fields. Audition the takes all the way through and keep the one that loops best: it should have no finale, no fade-out and no vocals.
2. **Drop the file in.** Save the chosen take as `assets-source/audio/music/<cue-id>/<cue-id>.wav`, or `.mp3` if your plan has no WAV export. Don't edit the file. It is the immutable source master, and its SHA-256 goes into provenance.
3. **Record the take.** Copy [`generation.template.json`](generation.template.json) to `assets-source/audio/music/<cue-id>/generation.json` and fill in:
   - the Suno song ID and link;
   - the model version;
   - your subscription (D21 requires the provider and subscription on every asset);
   - the date;
   - a note.
   `make audio-master` refuses a music source that has no complete `generation.json`.
4. **Master.** Run `make audio-master CUE=<cue-id>`. Plain `make audio-master` masters everything. The script:
   - trims silence;
   - folds the last 1.5 s over the head so the loop wraps cleanly (`loopCrossfadeSeconds` in [`assets-source/audio/cues.json`](../../assets-source/audio/cues.json));
   - normalises to −18 LUFS integrated with a −1 dBTP ceiling;
   - encodes `assets/audio/music/<cue-id>.webm` (Opus) and `.m4a` (AAC);
   - writes `assets-source/audio/music/<cue-id>/provenance.json`.
5. **Check.** Run `make audio-check`. It fails the cue on any of these:
   - loudness more than 1 LU off target;
   - true peak over −1 dBTP;
   - a clicking or level-jumping loop seam, or an interior dropout;
   - phase cancellation in a mono fold;
   - a hash mismatch.
6. **Audition.** Open [`assets-source/audio/review.html`](../../assets-source/audio/review.html). To use its gapless loop player, serve the repo root with `python3 -m http.server` and open `/assets-source/audio/review.html`.
7. **Commit.** Commit the source, `generation.json`, `provenance.json`, the two runtime files, `assets/audio/manifest.json` and `review.html` together.

## If a take fails the check

- **Loudness or peak.** The mastering report in `provenance.json` shows the gain, any limiting, and a `deviation` note when the cue needed more than 14 dB of peak reduction. A take with a few very loud hits and a quiet body can't reach −18 LUFS cleanly, so choose a steadier take.
- **Loop seam.** Raise `loopCrossfadeSeconds` for the cue in `cues.json` and master again. If the take still jumps in level at the wrap, the head and tail differ too much: choose a take that ends in the groove it starts with.

## Playback and memory

Music is marked `playback: stream`. One 3:30 stereo cue decoded to 48 kHz float32 is about 80 MB, and PRD §10 caps all decoded audio at 96 MB. So the runtime must stream music through a media element instead of `decodeAudioData`. The loop points in `assets/audio/manifest.json` are exact, but a media element's `loop` is not sample-accurate. The runtime stream therefore has to schedule the wrap itself, for example with a short crossfade between two elements. `make audio-check` counts only decoded cues against the budget, and it also prints the total if everything were decoded.
