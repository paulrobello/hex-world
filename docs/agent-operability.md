# Agent Operability

Hex World can be driven, observed, screenshotted and exited from the command line, natively and in the browser, with no OS screen-recording permission and no human. Screenshots are captured inside the app with Bevy's `Screenshot::primary_window()`, so they need only a window the app itself opens.

HUD path convention: `web/ui/hud.js` and `web/ui/hud.css` below are **built-site URLs**, not source files. Edit `web/ui/src/` (TypeScript and CSS); `web/ui/build.mjs` bundles it into `web/ui/dist/`, which Trunk copies into the site's `web/ui/`.

## Native CLI flags

Flags take the form `--name value`. A bare `--name` means `1`. Bad values log a warning and fall back to the default.

| Flag | Meaning | Example |
|---|---|---|
| `--scenario <name>` | Start scenario: `single` (the native default; the web build defaults to `play`, see [Web query parameters](#web-query-parameters)), `gate2000`, `kit` (the P1 kit family from `assets/kit/manifest.json`; missing pieces warn and are skipped), `water` (the hero-water look-dev patch: 12 hex cells with an ocean shelf, a beach and a river with a bend, `crates/hex-render/src/water.rs`), or `play` (the playable world: placement, undo/redo and bulldoze; see [Play scenario](#play-scenario)) | `--scenario play` |
| `--kit_hooks <none\|snow\|wet\|night\|dusk\|freeze\|autumn>` | Drives the §9.4 `masks` hook uniforms (snow, wetness, night emissive) for verification shots in the kit scenario. `dusk` sets the time-of-day block to `hooks::DUSK` (17:45, sun about 3° up) and works in the play scenario too, the grazing light that shows terrain relief (`docs/checkpoints/terrain-hump/`). Default `none` (noon) | `--kit_hooks snow` |
| `--kit_src <runtime\|fixture\|fixture_tiled>` | Kit scenario only. `runtime` (default) lays out the P1 family from `assets/kit/manifest.json`; `fixture` lays out three copies of the kit gate fixture (manifest `crates/hex-render/tests/fixtures/kit/manifest.json`, files served from `assets/kit/p1/fixture/`, kept byte-identical by `kit_scene::tests::served_fixture_matches_the_gate_fixture`); `fixture_tiled` is the same layout with the cap bound to a probe tileable set (`assets/kit/p1/fixture_tile/`, constant maps copied byte for byte from the fixture masks, so the gate fixture's provenance covers them: `kit_scene::tests::probe_set_is_a_copy_of_the_fixture_masks`), so the tileable forward and prepass shader branches run (web-smoke uses it) | `--kit_src fixture` |
| `--tonemap <agx\|tony\|aces>` | Kit, water and play scenarios only. Camera tone mapping (D4): `aces` (default, ACES fitted, from the default grade `rich-3`, owner 2026-10-14), `tony` (TonyMcMapface, the 2026-10-14 Q4 ruling: plain ACES fitted clips the shaded walls to black) or `agx` (AgX). It overrides only the grade's tone mapper: exposure, grading and backdrop stay the grade's, so `--grade tony` gives the whole Tony look. Other scenarios keep the P0 camera | `--tonemap tony` |
| `--grade <aces\|tony\|rich-1\|rich-2\|rich-3>` | Kit, water and play scenarios only. Look preset (`crates/hex-render/src/grade.rs`, owner 2026-10-14): tone mapper, exposure, Bevy `ColorGrading` and backdrop clear colour together. `rich-3` (default, owner 2026-10-14 after the grade comparison) is ACES fitted at EV100 12.5 with a +0.013 linear shadow lift before the curve and its own backdrop; `tony` is TonyMcMapface at EV100 12.9 with no grading (the default before `rich-3`), `aces` the earlier ACES fitted look at EV100 12.5 with Bevy's default clear colour, and `rich-1` and `rich-2` are TonyMcMapface with more colour (settings and measurements: `docs/checkpoints/grades/`, `docs/review/2026-10-14-grade-compare.html`). `--tonemap` and `--ev100` override the preset's own values in any key order. Switch live with `set_grade` | `--grade rich-2` |
| `--ibl <on\|off>` | Kit, water and play scenarios only. `on` (default) adds the prefiltered noon `EnvironmentMapLight` (`kit://p1/ibl/noon.{diffuse,specular}.ktx2`, intensity `lookdev::IBL_INTENSITY`) and sets the global ambient light to 0; `off` keeps the flat 400 ambient. With IBL on the kit forward pipeline samples 16 textures per fragment stage, exactly WebGPU's default limit (14 with `off`) | `--ibl off` |
| `--ev100 <f32>` | Kit, water and play scenarios only. Kit camera exposure (EV100, 0–20, default 12.5 from the default grade `rich-3`; the TonyMcMapface grades use `lookdev::KIT_EV100` = 12.9, owner-approved 2026-10-14; Bevy's default 9.7 clips the 30,000 lx sun). It overrides only the grade's exposure. The kit, water and play scenarios also aim their sun along the HDRI sun direction `lookdev::KIT_SUN_DIR` = (0.553, 0.742, 0.379); `single` and `gate2000` keep the P0 light | `--ev100 13.3` |
| `--tilt <auto\|on\|off>`, `--tilt_strength <0..1>` | Tilt-shift post pass (PRD §9.1, `hex_render::tilt_shift`): a sharp horizontal band at the camera's look-at point on the ground, blur growing with screen distance from the band and with depth difference, plus a small saturation lift. Fades out as the focus distance drops from 48 m to 12 m. `off` is the default (owner, 2026-10-14). `auto` is on from the Medium tier up (8 taps Medium, 16 High, 24 Ultra, off on Low) and only in the kit, water and play scenarios with `post=full`, so P0 baselines are unchanged (the game camera's default until 2026-10-14); `on`/`off` force it in any scenario. `T` toggles it at runtime. One pass, 2 sampled textures in the fragment stage (colour and prepass depth). `make shots-tilt` writes the off/on pair to `docs/shots/tilt-shift/` | `--tilt off` |
| `--grass <share\|percent%\|off\|sparse\|normal\|lush>` | Grass blade density in play (see [Grass](#grass)) as a share of Normal (28 blades per m² of grass ground): a number (`1.2`, the share; a bare number above 1.5 clamps, so `100` is 150%), a percentage (`120%`; `120%25` in a URL), or the stepped levels the slider replaced, `off` (0), `sparse` (0.5), `normal` (1, the default) and `lush` (1.5); `on` means `normal`. Clamped to 0..1.5 and rounded to whole percent. Blades draw only on the High and Ultra tiers, so this key does nothing on Low and Medium. On the web the key wins over the Settings sheet's remembered density for that visit. Change it live with `set_grass` | `--grass off` |
| `--grass_distance <near\|medium\|far\|very-far\|multiplier>` (also `--grass-distance`) | How far grass draws in play (see [Grass](#grass)): a multiplier on every grass distance (thinning, fade, build and drop radii), as a stop, `near` (1, the default: the tuning grass shipped with), `medium` (1.5), `far` (2: fade 68-116 m, thinning to 92 m) or `very-far` (3), or a number (`2.5`). Clamped to 1..3 and rounded to hundredths. High and Ultra only, like the density. On the web (`?grass_distance=`) the key wins over the Settings sheet's remembered distance for that visit. Change it live with `set_grass_distance` | `--grass_distance far` |
| `--tier <low\|medium\|high\|ultra>` | Quality tier (PRD §9.2). Without the key the tier is auto-detected once the render device exists (`hex_play::tier`, rules below under "Quality tier"); an explicit key always wins, even `high`. The tier sets SSAO (High and Ultra), the tilt-shift taps, the boid caps (Low 250 with up to 75 fish, Medium 500/150, High and Ultra 1,000/300) and the car cap (Low 75, Medium 150, High and Ultra 300; `play.car_cap`), both PRD §9.2's 25/50/100% agent caps (`QualityTier::agent_cap_percent`), and the water variant. The water scenario picks its variant from it: `low` has no refraction (alpha-blended, no transmission texture, no caustics) and 4 Gerstner waves; `medium` refracts with one caustic layer and 6 waves; `high`/`ultra` add the second caustic layer, the screen-space reflection march and 8 waves | `--tier medium` |
| `--water_clock <real\|fixed>` | Water and play scenarios. `fixed` advances water time by exactly 1/30 s per frame (motion captures); `real` (default) follows the frame clock | `--water_clock fixed` |
| `--clock <real\|fixed>` | `fixed` advances every Bevy clock (real, virtual and fixed) by exactly 1/60 s per frame (`TimeUpdateStrategy::ManualDuration`), so the 20 Hz car tick lands on every third frame and a scripted run replays identically; wall-clock flags such as `--exit-after-seconds` then count these 1/60 s frames. `real` (default) follows the system clock | `--clock fixed` |
| `--view <name>` | Gate camera view: `strategic` (default, whole world from 900 m) or `closeup` (40 m above tile (3, 2)). Unknown values warn and fall back | `--view closeup` |
| `--shot <name>` | Select the scenario and save `target/shots/<name>.png` at frame 120 | `--shot single` |
| `--exit-after <frames>` | Exit after N frames | `--exit-after 180` |
| `--exit-after-seconds <s>` | Exit after N wall-clock seconds | `--exit-after-seconds 10` |
| `--screenshot-after <s>` | Save one screenshot after N seconds, named by `--shot` or `screenshot-after` | `--screenshot-after 2` |
| `--photo-export <1\|2\|4>` | At frame 120, queue a `photo_export` at that scale named `photo-<n>x`: the game camera renders offscreen at n times the window's logical size and saves `target/shots/photo-<n>x.png` (see [Photo mode](#photo-mode)) | `--photo-export 4` |
| `--script <file.json>` | Run a command list (see below). A missing or invalid file exits with code 2 before the window opens | `--script scripts/shots/gallery.json` |
| `--thumbs` | Native only. Renders the Legend inventory's tile thumbnails and exits (`crates/hex-app/src/thumbs.rs`, PRD §5.3). Forces the play scenario at 384x384 with `--post none --tilt off --fps off --clock fixed`, a magenta clear colour, no deband dither and the boids hidden, then shows each catalog tile alone at the origin by writing `PlayView`, so `hex_play::play` draws its kit pieces or placeholders exactly as in the game. One fixed camera on the play start camera's side (pitch 58°, 20° field of view, edge 0 on the right) frames every tile at one scale. It requests every kit pack and starts once all of them have loaded. Each tile is shown once to warm up pipelines and textures; then each distinct rotation (rotations of one orientation, `TileDef::same_orientation`, share one image) is captured to `target/shots/thumbs/<tile>-r<k>.png`, with the mapping in `target/shots/thumbs/plan.json`. The frame a capture lands on depends on pack loading and screenshot readback (wall time), so the animation clocks are pinned instead: every frame of the run holds `Time` at 10 s elapsed (with the normal 1/60 s delta) and the water clock at 10 s, so wind, grass, windmill sails and water draw one phase in every capture, whatever its order in the run. Once the last capture is encoded it sends `AppExit` that frame and arms a watchdog thread: if the process has not exited 20 s later (a teardown that never finishes, for example the main thread waiting on a render-thread frame that never completes), it prints `every image is written but the app did not exit` and exits 3, so `make thumbs` fails instead of hanging. It overrides `--scenario`, `--size`, `--post`, `--tilt`, `--fps`, `--clock`, `--shot`, `--script` and the exit and screenshot timers; look-dev and quality keys such as `--tonemap`, `--ibl`, `--ev100`, `--shadows`, `--cascades`, `--tier` and `--seed` pass through and change the images, so `make thumbs` passes none. Use `make thumbs` | `--thumbs` |
| `--size <W>x<H>` | Fixed, non-resizable window at scale factor 1, so PNGs are exactly W by H | `--size 1280x800` |
| `--seed <u64>` | Stored in state for determinism. The boids derive their spawn points from it (see [Boids](#boids)); later animation reads it too | `--seed 1` |
| `--no-anim` | Stored flag; later animation systems read it to freeze motion | `--no-anim` |
| `--dump-state <path>` | Write the state JSON on every exit path, including closing the window | `--dump-state target/state.json` |
| `--load <path>` | Native only. Load a `.hexworld` save (PRD §12.2) before any `--script` command runs, once the scene is ready. A refused file logs `load refused (<code>): <reason>` and leaves the start world. Use with `--scenario play` | `--scenario play --load target/w.hexworld` |
| `--save <path>` | Native only. Write the world as a `.hexworld` file on every exit path, beside `--dump-state` | `--scenario play --script s.json --save target/w.hexworld` |
| `--diag` | Enable diagnostics | `--diag` |
| `--gpu_timing <on\|off>` | Per-pass GPU time in `diag().gpu` (`hex_play::gpu_timing`), default `off`. Marker compute passes with pass-boundary timestamp writes sit between Bevy's `Core3d` passes (WebGPU `timestamp-query`, Metal stage-boundary sampling). Each reads a texel of the texture the passes before it wrote and stamps its end, and each frame's queries are resolved a frame later, so a stamp means those passes finished (the module docs say why each is needed). That serializes the passes and adds 11 tiny passes per frame, so measure frame-time budgets with it off. All of that is native only: in Chrome the dependent markers hung the page, so the web keeps plain start-of-pass markers, whose frame `total` is usable but whose split is not (the stamps cluster in `preprocess` and `prepass`). Take per-pass numbers from native runs. Without `timestamp-query` it reports `supported: false` and nothing else changes. `HEXW_GPU_TIMING_DEBUG=1` (native) logs one frame's raw stamps every 200 frames | `--gpu_timing on` |
| `--layout <name>` | Gate static geometry: `entities` (default, one entity per piece per LOD), `chunks` (per chunk, LOD and material, all static pieces merged into one mesh at the chunk centroid; `VisibilityRange` applies per chunk), or `instanced` (the PRD §6 shipping shape: one GPU instance buffer of `{transform, material}` grouped by kit mesh and chunk; per view the CPU culls chunks, picks each chunk's LOD from the camera distance to its centroid at 150/400 m, and issues one draw per (kit mesh, LOD) through one pipeline that reads a 40-entry material palette; it draws into the main pass, the depth/normal/motion-vector prepass and every shadow cascade; `crates/hex-render/src/instanced.rs`). Vehicles stay individual entities | `--layout instanced` |
| `--chunk <n>` | Hexes per chunk for `layout=chunks` and `layout=instanced`: `7` (default) or `19` | `--chunk 19` |
| `--shadow_casters <all\|large>` | Which static pieces cast shadows. `all` (default) or `large`: props and every LOD2 piece stop casting (`NotShadowCaster` in the entities layout, no shadow draw in the instanced layout; the chunks layout merges props with large pieces, so there it drops LOD2 only) | `--shadow_casters large` |
| `--cascades <n>` | Directional shadow cascades: `2`, `3` or `4` (default) | `--cascades 3` |
| `--shadow_dist <m>` | Cascade maximum distance in whole metres, above the 120 m first-cascade bound. Default `2000` | `--shadow_dist 800` |
| `--post <name>` | `full` (default: TAA, SSAO, bloom, DOF) or `none` (all four off, MSAA stays off) | `--post none` |
| `--fps <on\|off>` | On-screen FPS counter (`60 fps \| 16.4 ms \| p95 17.1`, top-right, Bevy UI text). Default `off` (owner, 2026-10-19: the Settings performance readout replaces it for players); `on` or the **F3** key shows it. It is a persistent UI entity, not a `SceneEntity`, so `scenario` commands keep it. The perf gate passes `fps=on` (`PERF_FPS=off` hides it) | `--fps on` |
| `--debug <list>` | Developer overlays on from the start, a comma list of `lod` (LOD tint), `lod0`, `lod1` or `lod2` (Force LOD), `perf`, `grid`, `sockets`, `colliders`, `scatter` and `networks`. Unknown names warn. Never persisted, so a load without the flag starts with every overlay off. See [Debug overlays](#debug-overlays) | `--debug grid,lod,lod2` |
| `--shadows <on\|off>` | Directional-light shadow maps (`cascades` cascades). Default `on` | `--shadows off` |
| `--present <mode>` | Native only. `fifo` (default, vsync), `immediate`, or `novsync` (Bevy `AutoNoVsync`: immediate, else mailbox, else fifo). Use `novsync` for uncapped frame times | `--present novsync` |

Every exit path waits until pending screenshots have been written. The gate keys (`layout`, `chunk`, `post`, `shadows`, `shadow_casters`, `cascades`, `shadow_dist`, `kit_hooks`, `kit_src`, `tonemap`, `grade`, `ibl`, `ev100`, `tilt`, `tilt_strength`, `tier`, `water_clock`, `grass`, `grass_distance`) are read on every scene build, so a `scenario` command keeps them. Unknown values warn and fall back to the default.

## Environment variables

These are process environment variables, not URL parameters. Unset means the variable is absent. The source column names the consumer (paths are relative to the repository root). Cargo-provided build variables such as `CARGO_MANIFEST_DIR` are not game tunables. Make arguments such as `BLENDER`, `PIECE` and `*_DOCS` are Make variables, not additional runtime environment settings.

## Web query parameters

`shot`, `scenario`, `view`, `diag`, `exit-after`, `seed`, `no-anim`, `layout`, `chunk`, `post`, `shadows`, `shadow_casters`, `cascades`, `shadow_dist`, `fps`, `kit_hooks`, `kit_src`, `tonemap`, `grade`, `ibl`, `ev100`, `tilt`, `tilt_strength`, `tier`, `gpu_timing`, `water_clock`, `clock`, `grass`, `grass_distance`, `photo-export`, `debug`, with the same meanings as the flags. `grade`, `grass` and `grass_distance` win over the Settings sheet's remembered colour grade, grass density and grass distance for that visit. Example: `http://127.0.0.1:8094/?scenario=gate2000&view=closeup&diag=1`.

The web build's default scenario is `play`: the bare URL (and an unknown `scenario` or `shot` name) opens the game with the Legend HUD. Every other scenario stays reachable by query, for example `?scenario=single` for the one-tile look the native build opens on (`args::default_scenario`). The web galleries (`e2e/shots.mjs`) and web-smoke's Single case load `?scenario=single` explicitly.

`wgsl_compat` (`0` or `1`) controls `web/wgsl-compat.js`, which inlines the WGSL `let` texture and sampler handle aliases that browsers without the `texture_and_sampler_let` language extension (Safari 27) reject. `1` forces the rewrite on, `0` turns it off, and by default it is active only when the browser lacks the extension. `window.__wgslCompat` is set before the app loads (absent when WebGPU is unavailable) and holds `{ active, native, modules, rewritten, aliases, unhandled, ms }`: `active` is whether the rewrite is on, `native` whether the browser supports the extension, `modules` and `rewritten` count the shader modules seen and changed, `aliases` the aliases inlined, `unhandled` the bindless aliases left alone, and `ms` the time spent rewriting.

`frame_latency` (web only; `1` to `8`, or `off`/`0`; default `3`, owner decision Q7 of 2026-10-14) sets `web/frame-latency.js`'s bound on frames in flight, which is on by default: an animation frame that submitted WebGPU work counts as in flight until `GPUQueue.onSubmittedWorkDone` resolves, and while that many frames are in flight the next `requestAnimationFrame` callback waits. That is the bound wgpu's native surface keeps. `?frame_latency=off` (or `0`) patches nothing; any other value outside 1 to 8 is ignored with a console warning and the default applies. It exists for uncapped runs, where the page outruns Chrome's GPU process and the queued work comes back as 25–90 ms main-thread stalls (`docs/perf/stall-tail/`). At 60 Hz the queue never forms and the limit changes nothing measurable. `window.__frameLatency` (`{ limit, source, inflight(), deferrals() }`, `source` is `"default"` or `"url"`) is set when it is active, and the page logs `frame-latency: limit 3 (default)` at load. `make web-smoke` checks the bare URL (limit 3, `default`), `?frame_latency=2` (limit 2, `url`) and `?frame_latency=off` (not patched). `e2e/stall-probe.mjs` passes `frame_latency=off` in its base keys, so its baseline arms still measure the unlimited page.

`version_poll` (web only; seconds, at least 1) shortens how often the HUD checks `version.json` for a newer deployed build (default every 180 s, see [New version available](#new-version-available)). Zero, negative or non-numeric values keep the default. `e2e/version.mjs` uses `version_poll=1`.

### Quality tier

`hex_play::tier` picks the tier when no `tier` key is given. The static rules run once the render device exists, first match wins, and never pick Ultra:

1. A CPU device or a software rasterizer (SwiftShader, llvmpipe, lavapipe, softpipe, Microsoft Basic Render): Low.
2. `max_texture_dimension_2d` below 8192: Low.
3. `max_storage_textures_per_shader_stage` below 5: Medium (Bevy's SSAO needs 5, and High's AO is SSAO).
4. Web (the adapter is masked: `BrowserWebGpu | Other`, no name): High with `texture-compression-bc`; Medium with ASTC only (a mobile-class GPU) or neither. WebGPU's baseline of 16 sampled textures per stage is the design target, not a downgrade.
5. Native: an `Apple M<digit>` name is High (wgpu reports Apple silicon as integrated, so the name rule comes first); a discrete GPU is High; integrated, virtual and unknown devices are Medium.

On the web a warm-up probe then reads the real frame time of frames 50 to 109 (it decides ten frames before READY, so a step lands before harnesses act). Frames of 250 ms or more are hitches and dropped; with fewer than 30 left it is inconclusive. A median above 25 ms steps the tier down once. A change rebuilds the scene like `set_tier`. Natively there is no probe, so native checkpoints stay deterministic; `make thumbs` pins High. On this machine (Apple M4 Max) native detection gives High; see the P2 report for the web result.

**The player's choice.** The Settings sheet's Quality list (Auto, Low, Medium, High, and Ultra where detection lands on High) sends `set_tier`, and the choice is the save's `quality`: a quality or tilt-shift change queues an autosave, and loading a save applies its quality unless a `tier` key is set. Auto is checked while `tier.source` is `default`, `detected` or `probe`.

**Changing quality (owner report 2026-10-14).** A change stalls the page. On the 208-tile world of `e2e/water-world.mjs` (`e2e/tier-stall.mjs` measures it, 2026-10-14, host load at most 13.6; `docs/checkpoints/tier-change/`): the first change to Medium in a session took 0.48 s (a 0.38 s rebuild frame, then a 0.1 s one), later changes 0.21 to 0.22 s (0.14 to 0.15 s, then 0.06 s); no asset is fetched again. The layer adds about 10 to 50 ms before the rebuild (the two frames before `set_tier`) and clears 17 to 67 ms after the last slow frame. With the system's Metal shader cache cold, the browser's GPU process also compiles the new tier's pipelines after the rebuild frame and presents nothing meanwhile: the first run measured 3.75 s, 3.2 s of it in `MTLDevice::newLibraryWithSource`. A pick in the Quality list first shows the quality-change layer (the loading panel over the dimmed world, `Rebuild` in `web/ui/src/loading.ts`), waits two animation frames so it is painted, then sends `set_tier`; the layer clears once `tier.requests` has passed the count read at the send and `tier.rebuilding` is false, so a no-op clears as soon as it is handled. While it is up it takes the pointer and the Hud swallows key presses (releases pass, so a held camera key does not stick); further picks are ignored. A rebuild the overlay did not send (a resumed save's quality) shows the same layer from `tier.rebuilding`, from the frame after its rebuild, and the loading layer waits for `tier.rebuilding` to clear before it fades, which covers detection and the warm-up probe before READY.

**Tilt-shift across a tier change.** A rebuild resets tilt-shift to the new tier's default (off by default; on from Medium up only with `--tilt auto`) until the player toggles it themselves: the Settings switch (a `tilt` command with `on`) or the `T` key. A strength-only `tilt` command (the Settings slider) is not a toggle and does not count. From then on a tier change keeps their toggle and strength and takes only the new tier's tap count (`hex_render::tilt_shift::TiltPinned`, `kept_tilt`; `state.tilt.chosen`). The flag travels in the save (format v2 `tilt_shift_chosen`, owner decision A21): loading a save restores it, so a world the player toggled tilt-shift in keeps their toggle, and any other save (an autosave resume included, and every v1 file) puts tilt-shift back to the tier's default (`TiltTierDefault`) with tier changes still driving it.

### Host-load rule for timing runs

`e2e/perf-load.mjs` guards every timing run in `perf-gate.mjs`, `perf-matrix.mjs`, `perf-tilt.mjs`, `perf-water.mjs` and `perf-passes.mjs`, on web and native. Every budget script pins `tier=high` (PRD §10 sets the budget on High), since a missing key now means auto-detection:

- **Limit.** The 1-minute load average must be at or below `PERF_LOAD_LIMIT` (default 15) immediately before and immediately after each run.
- **Before a run.** The guard polls every 10 s for up to 10 min, or up to `PERF_LOAD_WAIT_MIN` minutes when that is set. If the load is still over the limit, it fails loudly.
- **After a run.** If the post-run load is over the limit, the run is discarded and re-run. After 3 retries the guard fails.
- **Recorded fields.** Each recorded run carries `load_before`, `load_after` and `load_discarded`. The matrix summary carries `max_load_accepted`.

Timing taken without this guard is not evidence.

## Play scenario

`--scenario play` draws the game world held by `hex-app` (`crates/hex-app/src/game.rs`). It opens with one meadow at `(0, 0)` and follows the PRD §4.1–4.2 rules from `hex-core`. Tiles use kit pieces from `assets/kit/manifest.json` where the tile references them and the piece's pack has loaded (see [Kit streaming](#kit-streaming)), and plain placeholders otherwise: a coloured prism per biome, dark road and blue river strips meeting at a hub, and beige blocks for pending houses, pads and hero props.

Hero variants (PRD §6 Variety): a hero slot authored as a piece listed in `hex_core::HERO_VARIANTS` may draw one of its variants instead, picked by `hex_core::hero_piece(def, cell, slot)` from a SplitMix64 hash of the cell and the slot index. Today a `house_cottage` slot draws `house_longhouse` or `house_cottage_b` (slate roof, gabled porch, a stack at each gable), the `house_twostorey` slot draws `house_twostorey_b` (jettied, hip-roofed) or `house_twostorey_c` (a stone-and-render T plan with a front cross wing and an end stack), the oak tile's `tree_hero_oak` slot draws `tree_hero_oak_b` (forked, east-leaning, a heavy low limb) or `tree_hero_oak_c` (low, broken four-lobed crown under two bare dead leaders, a stag head), and the farm's `barn_red` slot draws `barn_red_b` (a catslide roof over an open lean-to shed, a ridge cupola; `docs/checkpoints/barn_red_b/`, play shots from `play.json` there with farms at (0, 1) and (-1, 0), which draw it, and (1, 0), which keeps `barn_red`), and the windmill slot draws `windmill_b` (a white smock mill on a brick base with a stage; the origin keeps `windmill`), each slot varying about one time in three (`VARIANT_ONE_IN`); a slot with several variants splits that share evenly (`variants[(h / 3) % n]`), so a cottage slot keeps the cottage two times in three and draws each variant about one time in six (the two-storey slot likewise), and a house cluster shows any two of the three cottage designs beside any of the three two-storey designs. The pick depends on the cell alone, so saves carry nothing for it and a ghost previews the same houses the placed tile draws. Every consumer of a hero piece resolves it through `TileDef::hero_pieces(cell)`: the drawn tile, the ghost, walk obstacles and photo picks, grass exclusions and bird perches. The pack loader and scatter masks, which are per tile and not per cell, take every option of a slot (`TileDef::hero_options`; scatter clears the widest). `hex_core::VARIANT_PICK` switches the rule to one pick per cluster (`PerCluster`) or a fixed slot (`FixedSlot(n)`). `cargo test -p hex-core longhouse_cells -- --ignored --nocapture` prints the picks near the origin. The thumbnail cell, the origin, draws both cottages and `house_twostorey_c`, the authored `tree_hero_oak`, and the authored `barn_red`. The in-world affordances are the Legend direction's (`design/ui/legend/in-world.md`, `crates/hex-play/src/play/affordances.rs`):

- every free slot: a neutral 2 px outline dashed 6 on 7 off at ground height, fading out (160 ms) in bulldoze and photo mode
- the hovered slot: an ink outline at 90% and a 4% ink fill, crossfading in 120 ms; while another slot is pinned, the slot under the pointer gets the same outline (a click there pins it)
- the ghost, 150 ms after a slot is hovered or pinned: the selected tile's own kit pieces at the ghost's rotation (base, centre and lane edge pieces, hero props, and the tile's seeded scatter exactly as it will land: the placed tile's prepared ground, the seed `cell_seed(world seed, cell)` and each instance's transform under the rotated root; LOD0) drawn see-through at 45% by `crates/hex-play/src/play/ghost.rs`, tinted per part (base by biome, lanes by socket kind, trees, buildings, and ground props such as rocks and wildflowers; on coast, ocean and river tiles each ground part by its manifest material slot instead: grass, dry and damp sand, seabed or river bed, stones), with a flat water surface at the water level where the tile's own water field puts water (the seaward side of a coast, the whole ocean, a river's channel), desaturated 30% and tinted 15% toward ink, fading in over 120 ms. Their `GhostMaterial` (`assets/shaders/ghost.wesl`) binds one uniform and no texture and stays out of the prepass and shadows, so no pipeline gains a sampled texture beside refracting water. Under it a ghost-fill cap breathing 100% to 55% over 2.4 s and a 2 px ghost-line outline dashed 10 on 8 off (3 px solid while the slot is pinned). While a pack the tile draws from is still streaming there is no mesh: the outline, the edge colours and road (18 px), river (22 px) and rail (11 px) lane strokes at 60% stand in, and the meshes replace the strokes when the pack lands. The state JSON's top-level `ghost_meshes` says which is drawn
- the tile's own socket colours: on each edge, a 5 px line in the ghost tile's socket colour at its current rotation along the middle 72% of the edge, 11 px inside the rim, so the rotation reads without the sheet
- edge glow on the ghost's rim: compatible 7 px solid with two halos, incompatible 7 px dashed 14 on 9 off with two halos and a 14 px cross tick, no neighbour 3 px neutral; drawn emissive (×2.5) for bloom. The glow fades in over 120 ms whenever the ghost changes (rotate, retarget)
- socket key marks: on each touched edge, a 4 px line in the neighbour's socket colour along the middle 40% of the edge, 11 px outside the slot (on the neighbour's side, facing the tile's own colour across the edge glow)
- a refused placement or bulldoze pulses the incompatible glow or the blocked outline once over 240 ms (core 7 to 13 px)
- bulldoze: a removable tile gets a 4 px solid incompatible outline with an 8 px halo and a 12% fill; a tile whose removal would split the world gets a 4 px incompatible outline dashed 10 on 8 off, and the tiles it would cut off (every part but the largest) a 45° ink hatch every 10 px over sheet blue at 35% with a 2 px dotted ink outline; the last tile gets the dashed outline alone
- a placement flashes the slot's rim in ink (×4) for 80 ms

Widths are screen-space pixels at a device pixel ratio of 1 (multiplied by the window's scale factor), constant at every zoom: each line segment is a quad whose vertex shader (`assets/shaders/affordance.wesl`) projects both endpoints and pushes the corners out along the screen-space normal by the half-width in pixels. Dashes, the key marks' inset, the ticks and the hatch are in pixels too. The material binds no texture and draws without a depth test, over the world.

Water tiles (river, the spring `river_spring`, the fork `river_fork`, the three coast tiles `beach`, `beach_outer` and `beach_inner`, the river mouths `river_mouth` and `river_mouth_l`, and ocean) draw the approved water material (`crates/hex-render/src/water/tiles.rs`): a hex water surface on ocean, coast and river-mouth tiles, a 10 m strip along each river segment, one surface over a spring's pool and stream and over a fork's three arms, and the underwater cut face on every water edge with no matching water across it, rebuilt on place, bulldoze, undo and redo (each rebuild logs `play water: (q, r) <tile> r<rotation> exposed [...]`). A water tile whose base piece is missing from the kit gets a placeholder bed (river channel, beach slope, ocean floor) instead of its base. A missing centre piece does not: the base is the bed. The levels and profiles are the bed contract in `docs/kit/water-contract.md`. The play camera always carries the depth prepass and, from Medium up, screen-space transmission, and has no depth of field.

A placed tile plays the staged rise of PRD §4.4 from its `TileDef.rise` timeline (`crates/hex-play/src/play/rise.rs`; every MVP tile uses the default 2.0 s: column 0–0.6 s, cap 0.45–0.85 s, edges 0.8–1.2 s, props 1.1–1.7 s, agents 1.6–2.0 s):

1. Column: the tile root rises from 4.6 m below rest (ease-out) with a dust puff around the rim and a camera micro-shake (about 3 px, decaying, added before transform propagation and removed at the start of the next frame, so input, picking and the `camera` command never see it). Water beds rise with the column.
2. Cap: the column overshoots by up to 0.35 m and settles, with a slight dip.
3. Edges: centre and edge pieces (roads, pads, lane strips) snap in (ease-out-back), and water surfaces and cut faces fill from the tile base up to the water level.
4. Props: hero props grow in a staggered order, trees by scale, buildings floor by floor (two steps for a cottage, three for the two-storey, one for the single-storey longhouse).
5. Agents: the car sim mirrors the tile only from this stage (see [Cars](#cars)).

A new placement fast-forwards every running rise to its end state. Undo or redo takes the tile down: it sinks 4.6 m over 400 ms (ease-in) with a smaller dust puff around the rim, its water going with it, then despawns. A bulldoze sinks it over 700 ms inside a dust cloud that covers the hex (at most 120 particles: a swell across the hex, a billow past the rim and several metres up, and debris that falls back; clear 2.24 s after the bulldoze, the same layout every time for a given cell). The cloud is its first look at 80% of the size and 80% of the duration, every phase included (owner, 2026-10-14: `cloud` scales `cloud_base` and `cloud_layers` scales `CLOUD_BASE_LAYERS` in `hex_play::play::rise`); the render view's `bulldozed` cell tells the two apart, and both arrive as the `sink` rise cue. Under reduced motion neither sinks nor raises dust; placing on that cell again replaces the sinking tile at once. A tile that changes in place (a replace, and its undo or redo) sinks for 400 ms with no dust (`SinkKind::Replace`, never the bulldoze cloud), its parts released from the cell's rise, and the new tile's rise is held below ground for those 400 ms before its column starts (`riseStage` `sink` for the old tile, then the new tile's stages; the rise's `t` reads negative while it waits). Rebuilds (the core pack arriving, a switch into the scenario) draw every tile at rest; a streamed pack arriving swaps its tiles to the kit look in place, mid-rise included (see [Kit streaming](#kit-streaming)). Photo mode is only a flag so far: it hides the ghost and the slot ring.

### Grass

`crates/hex-play/src/play/grass.rs`, owner request 2026-10-14. Grass blades grow on the grass-covered ground of placed tiles near the camera, on the High and Ultra tiers only (none on Low and Medium), at the density of `grass` / `set_grass` / Settings → Graphics → Grass density (a 0-150% slider in 5% steps, 100% by default; disabled with a "High and Ultra only" hint on Low and Medium), out to the distance of `grass_distance` / `set_grass_distance` / Settings → Graphics → Grass distance (owner request 2026-10-19: a four-stop slider, Near, Medium, Far and Very far, multiplying every distance below by 1, 1.5, 2 or 3; Near by default). The distances below are Near's.

- **Where.** On the topmost LOD0 surface of a tile's ground pieces (scatter's surface) where the slot is a grass slot: a manifest slot whose tileable set is `grass` and that is not foliage (`meadow_base_cap`, `forest_base_rim` and `_edge`, `road_verge`, `river_grass`, `beach_grass`). Roads, sand, river beds, pads and hedges are not grass slots. No blade roots inside a hero prop's or scatter instance's ground footprint (houses, the windmill tower, the barn, hay bales and farm animals, the oak trunk, rocks, spruces, flower clumps; every planned instance, so a late pack never moves the grass). The houses, the barn and the bakery clear a rectangle: their collider's box (`scatter::GROUND_BOXES`, checked against the GLBs) turned by the hero's yaw plus 0.15 m (`grass::WALL_GAP`), so blades grow along their walls (owner 2026-10-19); every other piece clears a disc of its ground reach plus 0.05 m, or below the water level plus 0.3 m. A fence hero (the farm's paddock fence, `scatter::FENCES`) clears only a disc over each post (its half width times √2 plus 0.05 m: 0.142 m, 0.163 m for the gate posts), so blades grow under its rails and across the yard at the tile centre where the hero stands. The hex border is not an exclusion: it has no width, each tile owns the blades on its side, and the density holds up to the edge (a unit test holds the strip within 1 m of the border to the interior density within 10%), so neighbouring grass tiles read as one field. Each slot kind has its own height and share (mown verges, tall sparse dune grass).
- **Seeded.** A jittered grid seeded from `cell_seed(world seed, cell)` with a grass salt: the 150% set (42 blades per m² before the slot's share; 100% is 28, owner 2026-10-14). Each blade carries a `keep` value and a density of p% draws the blades whose `keep` is under p/150, so every lower value is a subset of every higher one and a slider move only changes how many of the uploaded blades draw, never the scene. Each blade gets a random scale (0.7 to 1.4 on height and width), yaw, lean and slight tilt, and a hue and lightness jitter (±0.04 of a turn, ±0.05, in a gamma-2 space so native and wasm agree). Slot widths are about 0.3 of the height, so blades read chunky.
- **Drawn.** GPU instancing (`crates/hex-play/src/play/grass_gpu.rs`): one shared blade mesh, two crossed tapered planes (an X from above, so it keeps a silhouette from any side; 10 vertices, 6 triangles, 156 bytes), and per tile one instance buffer of 32-byte blade records (root, yaw and thinning rank, height and width, unorm16 colour) holding the tile's whole 150% set ordered by `keep`, uploaded once. A density draws a prefix of that buffer, so a slider move changes only each group's instance count: no mesh is rebuilt and nothing is re-uploaded. Each tile's group is a child of the tile root: it rises and sinks with the tile and leaves with it on bulldoze, undo, replace and Start over; the ghost never draws grass. The draws are `NonMesh` items in the opaque and prepass phases of the camera (as the instanced static pieces are), culled per view against each group's bounds. Only tiles whose nearest point is within 60 m of the camera hold a group (dropped beyond 72 m), at most 3 new groups a frame, nearest first, and none started once the frame's grass builds have taken 4 ms. `off` keeps every group at 0 drawn blades, so turning grass back on changes counts only, and seeds no new tile while off. The vertex shader (`assets/shaders/grass.wesl`, pose in `crates/hex-render/src/grass_common.wesl`) scales blade height by a world-space clump noise (0.75 to 1.45 at about 0.35 per m, so lush patches stand taller), bends each blade from its root by the square of the height along it, thins blades by rank from 16 m to 46 m from the camera (35% kept, widened to hold the cover) and shrinks the rest to nothing between 34 m and 58 m, so no band pops. Every one of those distances (60, 72, 16, 46, 34 and 58 m) is the Near value times the `grass_distance` multiplier (`grass::Distances`), and the shader reads the scaled thinning and fade from the same `GrassParams` uniform `sync` writes, so the two never disagree; a farther stop builds the newly reached tiles under the same per-frame budget, a nearer one drops the tiles past its drop radius.
- **Wind.** `crates/hex-render/src/wind.wesl` (`hex_render::wind`, an embedded shader library that also drives the kit's foliage sway: trees, wildflowers, reeds and cattails): integer-hashed value noise, no texture, every layer scrolled with time along the prevailing wind (0.8, 0.6). Direction: a 90 m field and a 20 m detail field at 35%, swinging up to ±0.9 rad. Strength, a separate field: gusts (two octaves at 24 m and 12 m, 6.5 m/s downwind, up to 0.55; bent blades lighten up to 60% in a gust), patches (7 m, 2 m/s, ±0.14) and a base of 0.12. Flutter across the wind: 0.9 m noise at 4.5 m/s, ±0.07. The clock is Bevy's `Time` (1/60 s a frame under `--clock fixed`), so captures repeat exactly.
- **Pipelines.** Group 2 binds two uniforms (the wind clock and tuning, and per group, at a dynamic offset, its transform now and one frame ago and its season tag) and no texture, so the pipelines sample only the view's textures, fewer than the kit forward pipeline. Blades write the depth, normal and motion prepass (tilt-shift, refraction, SSAO and TAA see them; the motion vector uses the previous frame's wind and the group's previous transform), receive shadows and cast none. The colour is the slot's tint times the grass set's mean linear albedo with the blade's jitter, darker at the root, mixed toward a lighter, less saturated tip colour (85% at the tip) and lighter in a gust, with the §9.4 season tint from the group's `MeshTag`.
- **State.** `state().grass`: `density` (the share of Normal, 0 to 1.5), `distance` (the distance multiplier, 1 to 3), `status` (`on`, `off`, `tier` or `scenario`), `groups` (live blade groups), `blades` (drawn at this density), `triangles` (drawn), `instances` (blades held in the GPU instance buffers: each group's whole 150% set, so the same at every density), `mesh_bytes` (GPU bytes: the shared blade mesh and every instance buffer), `uploads` (instance buffers uploaded since start: one per new group, none on a density change), `per_m2` (28 times the share), the `thin`, `fade` and `build_radius` tuning at that distance, `last_build_ms` (the slowest single tile build, seeded set and instances, in the latest frame that built one), `last_swap_ms` (the slowest single density change, a group's drawn count, in the latest frame that changed one), and `tiles` (`[{q, r, tile, blades, area_m2, layout}]`, `layout` the seeded set's fingerprint).

### Kit streaming

Kit content loads by pack (PRD §10, `crates/hex-play/src/play/packs.rs`). Every piece and tileable set in `assets/kit/manifest.json` names its `pack`, one of `hex_assets::PACKS` in stream order:

| Pack | Pieces and sets | Why |
|---|---|---|
| `core` | meadow_base, the five road pieces; grass, soil, asphalt | The start meadow and its sets, and the road family every build starts from. Loaded on entry, before anything else |
| `props` | rock_small, wildflower_clump, hay_bale_round, hay_bale_stack, animal_cow, animal_sheep | Scatter props (meadow, pine forest, oak, windmill and farm tile rocks and flowers) and the farm tile's bales and animals. Streamed first |
| `forest` | forest_base, tree_forest, tree_oak, fern_clump, log_fallen and their variants; litter, bark | The pine forest and oak tile base and the pine forest's spruce, ferns and fallen log |
| `hero` | tree_hero_oak, tree_hero_oak_b, tree_hero_oak_c (budget class hero) | The oak tile's hero oak and its forked and stag-headed variants (also loads bark) |
| `village` | house_pad, house_cottage, house_twostorey, house_longhouse, house_twostorey_b, house_twostorey_c, house_cottage_b, windmill, barn_red, fence_paddock, wheat_field; plaster | The house cluster (also loads gravel for the driveway), the windmill tile's windmill, the farm tile's barn and paddock fence, and the wheat field (also loads gravel for its earth) |
| `water` | ocean_base, ocean_center, river_edge, river_straight_base, river_straight_center, river_bend_base, river_bend_center, river_road_bridge_center, river_spring_base, river_spring_center, river_fork_base, river_fork_center, the beach family, river_mouth_base, river_mouth_center, river_mouth_l_base, river_mouth_l_center; gravel | Ocean and river pieces; gravel is their seabed and river bed (also loads plaster for the bridge stone) |

- **Core.** The play scenario requests `core` on entry and draws the world once it has loaded. A core piece may sample only core sets (`parse_manifest` rejects it otherwise), and `kit_gate` requires a pack on every runtime entry, core for everything the start tile draws, and no hero-class piece in core.
- **On demand.** A pack is requested the moment a tile that draws one of its pieces is selected (inventory, number keys, `select_tile`; `hex-app` hands the selection over in `PackRequests`) or in the view: placed (also by undo, redo or a script) or previewed as the ghost.
- **Background.** After the first interaction (selecting another tile, or the first change to the view after the start world, such as a ghost or a placement; camera moves alone do not count), the remaining packs stream one at a time in `PACKS` order. Nothing streams before it, so the initial download is core alone (`make initial-download`).
- **Loading.** A pack fetches its pieces' GLBs, every map their slots sample (sets of other packs included) and the sets it owns, all at once. It is `ready` only when every file has loaded, so a tile appears straight in the textured kit look.
- **Hidden until its pack arrives (owner decision A10, 2026-10-14).** A placed tile that draws a piece from a pack that is not ready is hidden, with its pair edge pieces, scatter and water entities, and its empty slot shows a soft breathing outline (`affordances` `Key::Waiting`, the affordance shader, no texture; still under reduced motion; `hex_play::play::PlayWaiting` lists the cells). The placement registers at once: `play.tiles`, undo, saves and the rules see it, and `pack_waiting` lists it. When every pack it draws from is ready, its children are respawned with the kit pieces and it rises then (a tile hidden by a rebuild, such as a loaded world, appears at rest). It is not in `play.rising` and agents treat its cell as not drawn until then. The old coloured placeholders (biome prism, lane strips and hub, prop blocks, the water placeholder bed) remain only for pieces outside the manifest or that failed to load, whose pack is ready.
- **Status.** The state JSON reports `packs` and `pack_waiting` (see [State](#state)), and the log prints `play: pack <id> requested` and `play: pack <id> ready`.
- **Retries.** Every `kit://` read (pack files, the boid and car pieces, the IBL; web and native) and, on the web, every default-source read (the `shaders/` files the materials, the tilt-shift pass and the boid compute pass load) is retried when the request itself fails, as a reset or dropped connection or an HTTP error other than 403 and 404 does: the first request plus three retries after 0.5, 1 and 2 s (`hex_assets::bevy::RETRY_DELAYS`), each logged as a warning, and the pack, the boids or the pipeline wait through them. A file that still fails after the last retry, is missing (403, 404) or is a GLB that does not rewrite gives up visibly: an error naming the file (`kit://<path>`, or `shaders/<file>` for the default source) and that name in `assets.failed`. A shader that gives up leaves its pipeline uncreated (a failed boid compute shader keeps `boids.dispatched` at 0); the game keeps running. The feature then degrades as before: the pack goes ready with that piece drawn as a placeholder, and a failed boid piece leaves `boids.pieces` at `failed`.
- **Exceptions.** The `kit` and `water_kit` scenarios still load every piece they lay out at once, since they are gates. `--thumbs` requests every pack and waits for all of them.
- **Hold (native only).** `HEXW_PACK_HOLD_FRAMES=<n>` holds every streamed pack for `n` frames after its request before fetching it, so a capture can catch a tile while it waits. Disk loads otherwise land within a few frames. The streaming checkpoint uses it: `HEXW_PACK_HOLD_FRAMES=45 cargo run -p hex-app --release -- --scenario play --script docs/checkpoints/streaming/streaming.json --size 1280x800 --seed 1 --fps off --tilt off --clock fixed --water_clock fixed`. That run writes `target/shots/streaming-*.png` and `streaming-state-*.json`; their JPEG and JSON copies are in `docs/checkpoints/streaming/`.

### State

In the play scenario the state JSON's `tiles` is the world's tile count, and `play` holds the game (it is `null` in other scenarios). `events_pending` counts undrained events. Three top-level fields report kit streaming in play (all `null` elsewhere): `ghost_meshes` is `true` while the ghost draws its tile's kit meshes and `false` while it shows the outline fallback (a pack it needs is still streaming, or there is no ghost), and while it does, `ghost` reports `q`, `r`, `tile`, `rotation`, the scatter `seed` and `layout` fingerprint (hex strings; `layout` equals the `layout` of that cell's row in `scatter.tiles` once the tile is placed), `scatter` (instances drawn per piece), `water_surface` (it draws a water surface), `entities`, `mesh_material_pairs` and LOD0 `tris`; `packs` maps every pack id to `idle` (not requested), `loading` (requested, fetching or held) or `ready`, and `pack_waiting` lists the placed tiles drawn with a placeholder until packs arrive, as `[{q, r, tile, packs}]`. In every scenario `assets.failed` lists the files that failed for good, sorted: kit files as `kit://<path>` and, on the web, default-source files (the shaders) by their asset path, such as `shaders/boids_compute.wgsl` (empty when every load succeeded, see [Kit streaming](#kit-streaming), Retries).

### UI overlay (web/ui)

The player HUD is the Legend direction (mockups in `design/ui/legend/`, the system in the root `DESIGN.md` with its sidecar `.impeccable/design.json`, PRD D18 and §4.7) in vanilla TypeScript, an HTML layer over the canvas that changes the game only through bridge commands. `index.html` loads the built-site URLs `web/ui/hud.css` and `web/ui/hud.js` (sources in `web/ui/src/`, generated bundles in `web/ui/dist/`) and copies `web/` piecewise (`brand/`, `unsupported.html` and its backdrop `unsupported.jpg`, `wgsl-compat.js`, and `web/ui/dist` as `web/ui/`), so the overlay's sources and tooling never ship.

- **Unsupported page.** The WebGPU gate in `index.html` sends a browser without WebGPU, or without an adapter, to `web/unsupported.html`, the Legend S11 page. It carries the same CSP as `index.html`, takes its tokens, Manrope face and buttons from `web/ui/hud.css`, shows the app icon over a water capture (`web/unsupported.jpg`), and reads without script as the no-WebGPU variant. A small inline script (the CSP allows inline script) shows the adapter variant when `navigator.gpu` exists and names the browser and OS in the status line. `web/ui/build.mjs` emits the colour, shadow, motion (120 / 180 / 240 ms) and focus-ring tokens from the sidecar in front of `hud.css`; the type, spacing and radius scales sit at the top of `hud.css`.

- **Loading.** The layer shows the stage (engine download, then the renderer warming until `ready()`), the bytes actually downloaded (Resource Timing), and a Retry panel on a failed wasm download or after 120 s without `ready()`. It clears in every scenario, once `ready()` is true and no tier change is being rebuilt (`tier.rebuilding`). A quality change in play shows the same panel over the world (see "Changing quality" under [Quality tier](#quality-tier)). Only the play scenario gets the HUD; other scenarios poll the state once a second.
- **Per frame (play).** `pumpEvents()`, then `state().play`. The Tiles sheet's fit rules run in TypeScript from the catalog and socket table in `bridge-schema.json`; `web/ui/test/rules.test.ts` checks them against hex-core's legal rotations at every frontier slot of four scripted worlds (`rules-parity.json`: the play, water-play and coast checkpoints and a part-built coast). Undo and redo toasts name the action from a before/after diff of `play.tiles`.
- **Sticky slot.** The sheet's slot is `play.pinned` while a slot is pinned. Otherwise the sheet keeps the last slot pointed at until another slot, Esc or a placement replaces it, and while the pointer is off the canvas (over the HUD) the overlay re-sends `hover` for that slot, so R and the ghost keep working there. A pinned slot needs no re-sent hover. In the HUD, Esc with a pin only sends `unpin`; Enter places at the ghost's cell (the pinned slot when there is one); "Show the nearest slot" hovers and pins that slot. Each row's socket hex turns with the row's picture. Rows are the picker entries (`catalog.picker` in `bridge-schema.json`, from `TileCatalog::picker`): every tile on its own except the Beach Curve, one row for `beach_outer` and `beach_inner` (owner, 2026-10-20) that fits when either fits, counts both members' turns ("4 rotations fit", and the ghost tag's "Rotation 2 of 4"), and shows the member its turn is on. Both ids are named Beach Curve in toasts and tags.
- **Startup.** The engine's `inventory_open` starts `false` and the sheet is open by default, so the overlay sends one `toggle inventory` when it first sees the play state.
- **Reduced motion.** Once the engine is ready, in every scenario, the overlay sends `set_reduced_motion` with the OS `prefers-reduced-motion` value, and again whenever that setting changes. A scripted `set_reduced_motion` holds until the OS setting next changes. The HUD's own motion follows either source: the media query in CSS, and the engine flag (`play.reduced_motion`), which the overlay mirrors as `is-reduced-motion` on the root element every frame, so a scripted `set_reduced_motion` on cuts the HUD's transitions, keyframes and re-rank animations as the OS setting does.
- **Type sync.** `web/ui/src/bridge.ts` types every command, event and play-state field; its field tables must equal `bridge-schema.json`, which the hex-app test `bridge::schema::schema_matches_web_ui` regenerates from the Rust enums. A Rust change fails `cargo test` until `make ui-schema` runs, then `make ui-test` until `bridge.ts` matches.
- **Modifier clicks.** The Tiles sheet's footer carries a second line, "Shift-click place · ⌘-click replace" (Ctrl-click off macOS). A `tileReplaced` tags the cell "Replaced {old} with {new}" and plays the placement cues (`EVENT_ALIASES` in `audio-cues.ts`; the thunk lets the old tile's sink pass and waits for the new tile's `settled`); a refused replace tags the placed tile with the reason. Undo and redo of a replace toast "Undid: replaced {old} with {new}". The canvas prevents the browser context menu (winit does too), and on macOS a Ctrl+click the browser reports as the right button is sent as `replace` for the hovered cell.
- **Saved worlds (PRD D9, §12.2).** `web/ui/src/persist.ts` autosaves after every `tilePlaced`, `tileReplaced`, `tileBulldozed`, `undone` and `redone` (600 ms debounce) by sending `save` with a tag and the audio volumes, then writes `takeSave(tag)` to the slot of the world the save was taken from. On start it resumes the most recent slot through `load(bytes)`, or keeps the start world as "World n". Slots live in IndexedDB (`web/ui/src/slots.ts`): database `hex-world` version 1, store `slots` (keyPath `id`: `name`, `tiles`, `updatedAt` in Unix ms, `bytes`, `mix` (socket-kind edge counts) and `map` (up to 400 `[q, r, tile, rotation]` for the thumbnail)) and store `saves` (the `.hexworld` bytes by slot id), written in one transaction. The bar title is the world name, tile count and save state ("Riverside · 14 tiles · Saved", "Saving…", or "Autosave off" in the caution colour). The title opens the Worlds sheet (S10): rename, export `<name>.hexworld`, New world, Import (picker, or a file dropped anywhere on the page), and per saved world Load, Rename, Export and Delete (with a confirm). The Settings sheet's World tab has Start over: after an inline confirm it sends `new_world` and keeps the current world's name and slot, then autosaves the cleared world to that slot (when storage is on). A save carries the audio volumes (sent with each `save`), but the overlay does not apply a loaded world's volumes: the audio layer keeps this viewer's own levels from `localStorage`, so a world from another browser cannot change them. Every IndexedDB call is wrapped: no IndexedDB, an open that throws, errors, is blocked or stalls for 3 s gives no store, and the game plays on with autosave off and a caution toast offering Export. A refused import is a toast in plain words and leaves the world as it was. Switching worlds sends any pending autosave ahead of the load, so it lands in the world it came from. On `visibilitychange` to hidden and on `pagehide` a pending autosave is written at once from `saveNow` (the last frame), because a hidden page may never run the frame a queued `save` needs; the IndexedDB transaction is committed explicitly, and finishing it is best effort.
- **New version available (owner request 2026-10-15).** <a id="new-version-available"></a>Once the play HUD is up (other scenarios never poll), `web/ui/src/version-check.ts` (pure parts in `version-check-model.ts`) fetches `version.json?t=<now>` with `cache: "no-store"` every 180 s (`version_poll` in the address shortens it), on window `focus`, on `visibilitychange` to visible and on `online`; focus and visibility checks within 15 s of the last are skipped. It never polls while `navigator.onLine` is false, and a failed request, a non-2xx status or a body without a hex `id` is silent (no console output, no UI): the next check retries. A page without `window.__HEX_BUILD` (no post-build step) never polls. After every check the page dispatches a `hexversioncheck` event on `window` whose `detail` says what it did (`no-build`, `busy`, `throttled`, `offline`, `same`, `newer`, `reported`, `bad-status`, `bad-body` or `error`); nothing in the page listens, and `e2e/version.mjs` waits on it. When the live id differs from the page's, the update note appears: a toast that never times out, in the slot above the toast (84 px from the bottom), with "New version available", a sub line and a Reload action (DESIGN.md, Toast). It hides with the HUD (H, photo mode, walk mode), so it never covers the tool bar or the photo UI. Reload calls `Persistence.settle()`, which writes a pending autosave at once (`saveNow`) and waits up to 4 s until no autosave is queued, asked of the engine or being written, then reloads. If that wait fails, the note says the world could not be saved and the action becomes "Reload anyway". With storage blocked the sub line says plainly "Autosave is off, so reloading loses this world. Export it from Worlds first." in the caution tone, and Reload reloads at once.
- **The viewer's camera (owner request 2026-10-14).** `web/ui/src/camera-pose.ts` keeps where this viewer last looked at each saved world, outside the world save, so flying around costs no save, no autosave and no undo entry. Every 2 s, when the camera moved since the last write, and on `visibilitychange` to hidden, on `pagehide` and before a world switch (Load, New world, Start over, Import), it writes the pose of the world on screen to `localStorage` key `hexWorld.camera`: one JSON object keyed by slot id, each `{orbit: {focus, yaw, pitch, distance}, walk, at}`, where `orbit` is `play.orbit` (the orbit camera, also while walking or in photo mode), `walk` is `null` or `{feet, heading, pitch, cell}` from `state().walk` while walk mode is on, and `at` is the write time in Unix ms. Only a stored slot records (none before the start-up resume settles, for an unsaved start world, or with IndexedDB blocked), at most 64 poses are kept (the newest), a deleted slot's pose goes with it, and poses of slots no longer stored are dropped on start. When the start-up resume or a Load opens a slot, its pose comes back once the load has left walk and photo mode (three frames with both off): `camera` puts the orbit back, and recording pauses until it reads back in `play.orbit`, so the loaded save's own camera is never written over the pose. A walk pose then waits until its tile is walkable ground (the `core` pack ready and the tile not in `pack_waiting`; other packs streaming in the background do not hold it) and sends `walk` on and `walk_to` with the feet, heading and pitch, so leaving walk mode returns to the saved orbit. The pointer lock needs a gesture, so walk mode resumes behind the walk hint's "Click to look around". A walk pose whose tile is no longer placed (bulldozed, or off the map) stays in orbit at the saved focus, and a `walk_to` refused twice (`walk.blocked` set) leaves walk mode the same way; a restore that has not finished in 20 s stops where it is. **A restore yields to any other camera move** (coordinator report 2026-10-14: a script's `camera` right after a reload was moved away by a late restore, as a player's drag would be). It takes the first `play.orbit` it sees once the world is up as the load's own camera (the state that arrives with the `loaded` event already holds it, also while a walk or photo exit writes it back). Until its own `camera` reads back, any orbit that is neither that camera nor the saved pose ends the restore with outcome `yielded`: while settling it sends nothing, and after sending it never resends (the one resend after 1 s happens only while the camera still sits where the load left it). While a walk pose waits for its ground, moving off the restored orbit yields too, and walk mode is not entered. After a yield the moved camera is recorded over the stored pose at the next check. `hexWorld.cameraRestore()` reports the phase and outcome, and `e2e/ui.mjs` waits for it before its grade captures set their camera. A world with no pose (an import, a world from another browser) keeps the world save's own camera, and Start over keeps its slot but not a restore: the recentred camera is recorded over the old pose. Every `localStorage` call is wrapped: a store that throws or is missing records nothing and the game plays on.
- **Audio.** `web/ui/src/audio.ts` plays `assets/audio/manifest.json` through the Web Audio API. It fetches nothing until the first pointer or key press in the play scenario, which also creates the AudioContext at 48 kHz. It picks Opus/WebM, or m4a when `canPlayType` refuses WebM, and decodes `decode` cues (interface and placement one-shots first, then the ambience loops) within `decodedBudgetBytes`. Music cues stream through media elements. Game events fire the cues listed in each cue's `events`: placement one-shots are positional at the tile, the thunk waits for the tile's `riseStage` `settled`, and redo plays the undo cue a little higher. A water tile (any `River`, `Ocean` or `Beach` edge in its catalog definition) also plays a variant of the `place-slosh` pool with the thunk, at 0.7 times its level (owner request, 2026-10-20). River and coast tiles carry looped HRTF-panned emitters (`river-babble`, `surf`), up to three voices per cue, whose gain is the inverse-distance attenuation from the camera times a focus weight around `play.focus` that widens with `play.zoom` (`audio-mix.ts`). A non-positional bed from the same two loops follows the biome mix in view. Meadow and forest have no loop and no bed: they sound only through occasional one-shots from the scheduler table `ONE_SHOTS` in `audio-mix.ts`. Forest tiles play a random variant of the `forest-birds` pool every 12–40 s and of the `forest-leaves` pool every 20–60 s, and meadow tiles with wildflower scatter play `meadow-bees` every 45–120 s. The P3 tiles match by id: a `farm` plays `farm-cow` and, on its own timer, `farm-sheep` every 30–90 s; a `windmill` plays `windmill-creak` every 25–70 s; a `wheat_field` plays `wheat-rustle` every 20–60 s; and a `house_cluster` plays `well-windlass` (the windlass of its stone well) every 40–110 s, at level 0.25. Each plays at a matching tile within three hex steps of the focus, never repeats the previous variant, and is skipped (not queued) when muted, with the ambience bus at 0, before it decodes or with no matching tile in range. A pool's variants are the manifest cues whose `pool` names it. Cars sound on the ambience bus too (owner request, 2026-10-14): `carPulledOut` plays the `car-start` pool and `carParked` the `car-door` pool at the spot, and a car in its `road` phase in `play.car_list` plays `car-drive` once per trip, its panner and gain following the car. Each is at its level (0.4, 0.4, 0.3) times the focus mix, only within three hex steps of the focus, with at most three car voices, one per car, and a per-car rate within 5% (`carStep` in `audio-mix.ts`). A `carParked` whose cell holds a `bakery` also rings the `shop-bell` pool at the spot 1.2 s later, after the door, at level 0.35 under the same range and gates (`bellStep`). Trains sound there as well: each `trainDeparted` plays the `train-whistle` pool at the train's front (level 0.45), and every train in `play.train_list` running at 0.5 m/s or more chuffs `train-chuff` (level 0.3), its panner following the front and its gain the focus mix times its speed over the 6 m/s line speed, restarting while it runs on. Both are within four hex steps of the focus, with at most three train voices and one of each kind per train (`trainStep` in `audio-mix.ts`). The music playlist crossfades at equal power (6 s) between the mood cues `meadow-day`, `coast-breeze` and `hearth-town` by the biome mix in view, after a 30 s dwell. While photo mode is open (`play.photo_mode`) `photo-mode` takes over at once, and the mood's pick returns at once when it closes. `title-theme` and `discovery-stinger` are mastered but have no hook yet. With no music cue mastered the playlist stays idle. The buses and their defaults follow the Legend Settings → Audio mockup (master 80%, music 55%, effects 75%, interface 50%), except ambience, which defaults to 10% (owner, 2026-10-14). The Settings sheet's Audio tab sets mute and the five bus levels through the same `hexWorld.audio` calls (`setMuted`, `setVolume`), which scripts can also use.
- **Autosave off reads the same everywhere.** With storage blocked, the bar and the Worlds sheet's current-world line both read "Autosave off" (owner decision A16; the sheet used to say "Not saved"). `make ui-e2e` checks both.
- **Loading exits photo mode.** A `load` (a slot's Load, an import, the resume) or `new_world` that lands while photo mode is on leaves photo mode the normal way (`photoModeToggled` with `on: false`): FOV, exposure, lens and the agent pause come back as on any exit, and the camera is the loaded world's orbit pose (for a new world, the orbit camera recentred), not the free camera (owner decision A16).

### Photo mode

PRD §4.6, `crates/hex-app/src/photo.rs`. Photo mode follows `play.photo_mode`, so P, Esc, `toggle photo` and the overlay share one snapshot: entering takes the orbit camera's transform, FOV, exposure and lens, and leaving writes them back exactly. The camera entity stays the same and photo mode adds no prepass, so no kit or water pipeline gains a binding (kit forward stays at 16 sampled textures beside refracting water):

- **DOF `manual`** puts Bevy's `DepthOfField` on the camera (focus distance, f-number) with a sensor 60 times Bevy's default, so the diorama blurs like a miniature. The play camera carries no `DepthOfField` (it drops the gate's far-focus one), so the lens is inserted while Manual is chosen and removed for the other choices and on exit; it is a post pass with its own pipelines, so no mesh pipeline gains a binding. **`tilt`** drives the game camera's tilt-shift pass through `tilt_shift::TiltOverride`, focused by the panel with no zoom fade and its strength from the f-number (full at f/1.4, gone at f/22). **`off`** leaves the lens at the game camera's far focus. The player's own tilt-shift setting comes back untouched.
- **Click to focus** (owner request, 2026-10-14). The overlay (`web/ui/src/photo-focus.ts`) takes a left press and release on the canvas as a click when the pointer travels at most 4 px over the whole press and the press lasts at most 350 ms. Anything else is the drag that looks around, and the right button never focuses. The panel and bar take their own pointer events above the canvas, so a click on them never reaches the scene. A click sends `photo` `focus_at`, and `photo::focus_pick` resolves it on the CPU after `photo::sync`. The pick casts the ray through that pixel from this frame's camera transform, FOV and aspect, so it includes roll. It marches the ray over the walk ground's visible top (`WalkGround::top`: the kit ground pieces' LOD0 surface, and the water surface on water tiles) out to a view depth of 1,000 m, in steps of 1% of the distance (at least 10 cm), and refines the crossing by bisection. It also tests the drawn props walk mode treats as obstacles (`walk::OBSTACLES`: the three houses (cottage, two-storey and longhouse), the windmill, the barn, the hay bales, the cow and sheep, the hero oak, forest spruces, the oak tile's scattered oaks, small rocks, the fallen logs, the beach driftwood; the same drawn hero and scatter instances, with each one's position, turn and scale) and keeps the nearest hit (owner request, 2026-10-14). Each piece's volume comes from its loaded GLB (`walk::PieceShape`): the `<piece>_collider` footprint extruded from the collider's lowest point to the top of the piece's non-foliage LOD0 mesh, and for trees a crown of 10 height bands by 8 wedges fitted to the LOD0 foliage slots (every slot but `<piece>_bark`). A ray that enters a volume lands on the first LOD0 triangle it crosses, or on the volume where it slips through a gap in the leaves. Wildflowers are not pickable, and a piece whose GLB has not loaded yet is not either. Where no walk ground is built (another scenario, or the kit still loading) it uses the plane y = 0. `focus` becomes the hit's view-space depth (view z, which the tilt-shift shader and Bevy's lens both read), clamped to 1 to 1,000 m. With Tilt, `TiltOverride::focus_uv_y` puts the band on the clicked row. The slider runs 1 to 1,000 m so any click fits, and it follows a landed click (`focus_picks` moves). A ring fades at the click and the band preview shows on the new row. Both are overlay DOM, so no PNG export has them. No GPU readback, sampled texture or prepass is added.
- **Pause** (default on): the car sim skips its fixed ticks and keeps the last published poses (interpolating with the cycling overstep would rock each car), and the boid compute step is 0. Water and the rise keep their clocks.
- **Export** retargets the game camera to an uninitialised `Rgba8UnormSrgb` image at the export size for 8 frames (TAA settles), captures it with `Screenshot::image`, then hands the camera back to the window. No camera draws to the window for those 9 frames. Bevy 0.20's `prepare_windows` then acquires no swap-chain texture for the window, so nothing is cleared or presented and the window keeps showing its last frame: the backdrop flash the 2026-10-14 queue warned of does not occur (owner decision A14; this rests on Bevy's `prepare_windows` and `handle_uncovered_swap_chains`, and no engine change was needed). `make ui-e2e` captures the canvas during the 2× export, counts only captures with `photo.exporting` set both before and after, and fails if one's mean brightness moves more than 25% from the frame before the export; it logs the count, since a fast export can end before any bracketed capture. Native is not captured: a native window `screenshot` reads the camera output, not the presented drawable. Sizes past `max_texture_dimension_2d` are refused, and the web refuses 4× until it is tested for GPU memory: the photo sheet's 4× option is disabled and struck through with the reason under it. The lens's pixel blur cap scales with the export.

`make shots-photo` runs `docs/checkpoints/photo/photo.json` natively at 1280x800 with `--tilt off --clock fixed` (enter on the tilt preset, a manual-DOF close-up and the same frame with DOF off, the tilt preset with roll and exposure, one framing click-focused near with `focus_at` `[0.5, 0.85]` and then far with `[0.5, 0.2]` (`photo-06-click-focus-near`, `photo-07-click-focus-far`; the target fails unless the far click focuses farther on its own row and changes the image), level at eye height 40 m south of a hero oak before and after a click on its crown's middle (`photo-08-tree-before`, `photo-09-tree-click`; fails unless the click reports `tree` within 2% of 36.1 m, the oak mesh's view depth along that ray), a 4× export at 5120x3200, and exit back to the orbit camera) and copies JPEG stills, the state dumps and the export's measured size and mean to `docs/checkpoints/photo/`. Older checkpoint scripts that use `toggle photo` only for a clean frame send `{"cmd":"photo","dof":"off","pause_agents":false}` after it, so their cars keep driving and `--tilt off` still holds.

`make shots-photo-fx` runs `docs/checkpoints/photo/photo-fx.json` the same way: one still per effect, a combined look, its 2× export, the game camera after leaving photo mode and the state on re-entering, written to `docs/checkpoints/photo/photo-fx-*`. `scripts/photo-fx-check.py` fails it unless black and white has no saturation, the vignette darkens the corners against the centre, grain and aberration change the image, the 2× export keeps the viewfinder's vignette and colour, and the pass is off outside photo mode.

### Walk mode

PRD P8 (the walk half; drive mode is later), `crates/hex-app/src/walk.rs` over the ground in `crates/hex-play/src/walk.rs`. Walk mode follows `play.walk_mode`, so F, Esc, the HUD's Walk button and the `walk` command share one snapshot: entering takes the orbit camera's transform and FOV, leaving writes them back exactly.

- **Speed.** The walker walks at the walk speed setting, 5.0 m/s by default (owner, 2026-10-20), from 2.8 to 8.0 m/s (owner, 2026-10-14), and Shift sprints at exactly twice it. The Settings sheet's World tab has the Walk speed slider (0.1 m/s steps), which applies at once through `set_walk_speed` and is kept per viewer in `localStorage` (`hexWorld.walkSpeed`), outside the world save. Keys and scripted `walk_step` moves read the setting every frame, so a scripted move covers exactly speed × seconds on open ground.
- **Entering** puts the walker on the standable ground nearest the orbit camera's focus point (rings 0.5 m apart out to 48 m, then each tile's own ground nearest first), facing the way the orbit camera faced and 5° down. The eye is 1.7 m over the feet; the FOV is 60° (vertical) while walking. The near clip stays Bevy's default 0.1 m, which suits eye height. LODs follow the camera distance as always, so close pieces draw at LOD0. Walking draws a sky (`walk::walk_sky`): a Bevy `Skybox` of the IBL cubemap that lights the scene (`noon.specular.ktx2`) at the IBL's intensity and rotation, following the time of day's dimming; leaving removes it, so the orbit camera keeps the grade's dark backdrop.
- **Ground** is the topmost LOD0 surface of the tile's base, centre and lane edge pieces (the surface scatter stands on: meadow cap, road, beach slope, river banks and bed, the bridge deck), sampled in the tile frame through its rotation. Tiles hidden until their pack arrives are not ground; a tile drawn with placeholders stands at y = 0. The eye eases toward 1.7 m over the ground at 12/s, so kerbs and slopes glide.
- **Collision.** The walker is a 0.3 m circle. Moves are checked in sub-steps of at most 0.1 m and slide along whatever blocks them (each world axis alone). They stop at: a collider (`<piece>_collider` in the kit GLB, hulled to a convex footprint on the ground) of an obstacle piece (`walk::OBSTACLES`: the houses, the windmill, the barn, the bakery, the hay bales, the cow and sheep, the hero oak, spruces, scattered oaks, rocks, fallen logs, beach driftwood and the farm's paddock fence), placed with the hero prop's or scatter instance's transform under the tile's rest transform (wildflowers do not block). A collider of disjoint parts is hulled part by part: the paddock fence blocks as six run boxes, so the walker enters the paddock through its 3 m gate and stands inside it. A part outside its piece's collider has its own footprint (`walk::PIECE_POSTS`: `house_cottage_b`'s two porch posts, with the doorstep between them open); water deeper than 0.6 m on a sea tile (ocean, coast and river mouth; the surface is `water::tiles::WATER_Y`), so the walker wades into the shallows and stops at the shoreline. Rivers and spring streams are fords (owner, 2026-10-20): over water deeper than 0.6 m the feet hold 0.6 m under the surface, so the walker wades down the bank, crosses the channel with its eye 1.1 m above the water and climbs out on the far bank; a cell with no drawn tile (the map edge or an empty slot), with the body never overhanging it; and a step up of more than 0.4 m (a railing).
- **The world keeps running**: cars, birds, fish, water, the rise and audio. The audio listener is the camera, so it is the walker's head, and `play.focus` and `play.zoom` follow the walker (see [State](#state)). Placement, pins, bulldoze, rotate, undo and redo are refused while walking (`actionRefused`, reason "leave walk mode first"), the ghost, slot ring and bulldoze target hide, and pointer hover stops. Photo mode is refused while walking. Tilt-shift is off in first person whatever the setting (a zero-strength `TiltOverride`); leaving restores the player's own.
- **Saves never store walk state.** `save`, the page-hide `saveNow` and `--save` take the orbit camera from the snapshot, not the walker's eye, and entering or leaving touches no undo history. On the web the overlay keeps the walker per viewer instead (see "The viewer's camera" under [UI overlay](#ui-overlay-webui)). A `load` or `new_world` while walking leaves walk mode at the loaded orbit camera.
- **The HUD** hides behind a walk hint at the bottom centre ("Click to look around", the keys, and a Leave button with Esc) and a small centre mark. The bar's Walk button (the walker icon, tooltip "Walk around F") and F enter it. In the browser entering takes the pointer lock inside that click or key press (a refusal is caught; dragging still looks); losing the lock while walking (the browser's Esc) leaves walk mode, and a click on the canvas retakes it. Natively the mouse looks while a button is held.

### Debug overlays

Developer overlays (owner request 2026-10-14, `crates/hex-play/src/debug.rs`, `web/ui/src/debug.ts`), driven three ways: the Settings sheet's Debug tab, the `debug` command, and the `--debug <list>` flag or `?debug=` key. Every overlay is off by default and none is persisted: the world save, `SavedSettings` and `localStorage` never hold them, so a reload starts with everything off. An off overlay runs no system: each is gated by a run condition on the `DebugOverlays` resource (`debug::tests::off_overlays_run_nothing`), and `state().debug.work` counts overlay system runs, which stays 0 while all are off.

- **LOD tint** (`lod`): every LOD-tagged part (play kit pieces and pair edges, cars, the `kit` scenario and the entities and chunks gate layouts) wears one of three shared `StandardMaterial`s by its level: LOD 0 viridis yellow `#fde725`, LOD 1 teal `#21918c`, LOD 2 purple `#440154`, ordered by lightness so they read without hue. Its own material comes back when the tint turns off. It is a material swap, so the kit forward pipeline gains no sampled texture. The tab shows the key with each level's distance band and drawn count.
- **Force LOD** (`lod0`/`lod1`/`lod2`, Auto by default): pins every LOD-tagged part to one level by swapping its `VisibilityRange` (the other levels get a range that never draws); Auto puts the 150 m / 400 m bands back. Parts spawned while a level is forced take it at once. The `layout=instanced` gate path picks its LOD per chunk on the GPU and is not covered by the tint or Force LOD.
- **Performance** (`perf`): a corner panel on the web HUD (top left, under the bar; it stays while the Settings sheet is closed and hides with H) shows the frame rate, mean and worst frame time over the last second, entities, kit draws per level and their triangles, grass blades drawn (`state().grass.blades`), and the three slowest GPU passes with the GPU total when `gpu_timing=on` gives `diag().gpu.passes`. Natively the F3 counter stays the on-screen readout and the numbers are in `state().debug`.
- **Hex grid** (`grid`): gizmo outlines of placed tiles (white) and free slots (grey), and on the web each cell's `q, r` as a HUD label projected through `hexWorld.cellRect`.
- **Edge sockets** (`sockets`): each placed tile's six edges as gizmo lines in its socket colours (the in-world key mark colours), inset so two neighbours' marks on a shared edge sit side by side, with a tick toward the tile centre.
- **Colliders** (`colliders`): every walk obstacle footprint (houses, trunks, rocks) as a red gizmo loop at its ground height.
- **Scatter footprints** (`scatter`): each drawn scatter instance's ground footprint (`scatter::footprint`, scaled) as an orange circle, and every area grass keeps clear (`grass::exclusions`: scatter instances and hero props, with the prop gap) as a blue circle, or a blue rectangle for a rectangular building (the houses, the barn, the bakery).
- **Road and river graph** (`networks`, drawn by `hex-app` from the car simulation's mirror): every road and river link's centerline in its socket colour, each node as a small ring and each destination (car spawn and sink) as a larger white ring, so a broken road or an unreachable house shows at a glance.

The gizmos use their own config group with a negative depth bias, so they draw over tile tops, on WebGPU and natively. `state().debug` is `{lod_tint, force_lod, perf, grid, sockets, colliders, scatter, networks, lod: {by_lod, tris_by_lod}, frame: {fps, mean_ms, worst_ms, entities}, work}`. `lod` counts drawn LOD-tagged parts (visible in the camera or a shadow cascade) and their triangles per level, refreshed every 15 frames while LOD tint, Force LOD or perf is on; `frame` is refreshed while perf is on. Both hold their last values while off. `make ui-e2e` runs `e2e/debug.mjs`, which drives every overlay through the tab and the command, checks the counts follow Force LOD, and checks a reload and `?debug=` (captures in `docs/checkpoints/debug/` with `DEBUG_OUT=docs/checkpoints/debug`).

### Cars

`crates/hex-app/src/sim.rs` keeps a `hex_sim::Simulation` in step with the world: whenever the game state changes it diffs the world's tiles against the ones it last mirrored, so a removed tile is a bulldoze and a new or changed tile a place, whichever action caused it (place, bulldoze, the undo of either, redo). A tile edit despawns every car routed over that tile. The sim ticks at 20 Hz in Bevy's `FixedUpdate` (`Time<Fixed>` is set to 20 Hz; nothing else uses the fixed schedule) and only while the play scenario is shown. Each frame the car poses are interpolated between the last two ticks with `Time<Fixed>::overstep_fraction()` and drawn by `crates/hex-play/src/cars.rs`: one entity per car id, each one of the kit pieces `car_sedan`, `car_van` or `car_pickup` chosen by the car's seed and painted at runtime from a 12-colour palette carried as a per-entity `MeshTag`, so every car of a type and LOD draws in one instanced batch (until the car pieces load, or if they fail, every car draws as a placeholder mesh), standing on the road crown at y = 0.11 m. The default spawn rate is 0.05 cars per second per connected house, up to 300 cars.

Agents wait for the rise: in the play scenario the mirror diffs against the world minus every tile whose rise has not reached its agents stage (`CarSim::mirror_gated`, `PlayRises::agents_ready`), so a road joins the car network 1.6 s after it lands, or at once when the next placement fast-forwards it. Removals still apply at once. `SimPlugin` orders the render's play systems between the view writer and the mirror, so the gate reads the same frame's rise state.


### Boids

`crates/hex-play/src/boids.rs` runs one GPU compute pass (`assets/shaders/boids_compute.wgsl`) over a shared boid buffer that `BoidMaterial` (`assets/shaders/boid_material.wesl`) draws as the kit pieces `bird_starling` (x4 real size) and `bird_goldfinch` (x5, owner A11-Q2) and `fish_trout` and `fish_mackerel` (x2): one merged mesh per piece holds a copy of its LOD0 per slot it may draw (a bird species' mesh only its own flocks' slots, `boids::FormSlots`, so the two bird draws hold one copy per slot between them; each fish species' mesh every fish slot, since a fish's species follows the water each world spawns it in, and the vertex shader collapses a copy whose fish belongs to the other species, `boids::fish_form_draws`), and the vertex shader poses each copy from TEXCOORD_1 (wing flap and perch fold about the shoulder hinge, tail wag), lifts perched birds onto the canopy and offsets a river fish's UV0 into the river palette. Four draws: two bird species and two fish species. The CPU half, `boids/plan.rs`, decides everything and uploads it as read-only storage buffers; play never reads the flock back. Fixed-clock capture runs (`--clock fixed`) add `boids::FishTrack`, which reads the flock back each frame and reports `fish_track` in the state dump: fish seen upstream of a river mouth's fan (river or spring water, or the mouth tile at s < -3) and later past it (s > 6, coast or ocean water), or the other way round, counted once per fish (`river_to_sea`, `sea_to_river`) and per mouth cell in `mouths` (`q`, `r` and the two counts), credited to the last mouth tile the fish swam in, so a checkpoint tells `river_mouth` and `river_mouth_l` apart. Each readback is tagged with the frame, boid clock and plan it was copied under and folded in frame order 8 frames later (`boids::TRACK_LAG`), so the counts do not depend on when the GPU's map callbacks land; `samples` counts the readbacks folded in, `through` is the last frame folded, `digest` an FNV-1a hash of that frame's fish (slot, position and velocity bits; equal digests mean the same fish), and `skipped` the readbacks that never arrived within 120 frames. The compute pass reads every boid from `boids_prev`, a copy of the flock taken before it runs, and writes only the flock buffer, so the flock is the same every run on one GPU (reading neighbours from the buffer being written raced). Scenarios other than `play` keep the P0 stress flock: every slot a bird over an 800 m square, the budget the perf gate expects.

- **Budget.** `BoidBudget::for_tier` is the quality-tier hook: High and Ultra get 1,000 slots shared by birds and fish, Medium 50% (500, fish up to 150) and Low 25% (250, fish up to 75); the numbers below are High's. Fish get 12 per water tile (river, coast and ocean tiles past their rise's agents stage) up to 300. Bird slots are 75% of the slots the fish leave (`plan::BIRD_PERCENT`, owner A13: 25% fewer birds), and the remaining slots are idle: the compute pass parks them and the material collapses them, so they draw nothing. With 25 or more water tiles the split is 525 bird slots and 300 fish; with none it is 750 bird slots. Play does not fill the bird slots from the start (owner, 2026-10-14): a flock of 12 flies per `plan::LAND_PER_FLOCK` (4) land tiles (placed tiles past their rise without water), whole flocks within the bird slots (`plan::flying_birds`), and the rest of the bird slots stay idle. The single start tile has no birds; 10 land tiles fly 24, 50 fly 144, 200 fly 600 and 2,000 fly High's 744 (Medium caps at 372, Low at 180). A flock that the world gains flies in from 40 m past the sky's edge (the opening world's flocks start over it); a flock it loses keeps flying, outward and off the map, for 12 s (`plan::SlotKind::Leaving`) before its slots go idle, and turns back if the land returns first.
- **Birds** fly in flocks of `plan::FLOCK_SIZE` (12, owner U2) over the world's bounding box at 22–44 m. Each flock is one species (`plan::flock_species`): flocks alternate between `bird_starling` and `bird_goldfinch` from a first species chosen by a hash of `--seed`, so a world with two or more flocks shows both and an oak's perches hold one species; the spawn and heading streams do not depend on it. A flock spawns within 6 m of its own seeded point in the sky, and a bird coheres and aligns only with its own flock's birds within 22 m while keeping 3 m clear of every bird (before U2 every bird cohered with every other within 22 m, so the sky held one cloud). Roosts come from tile data: each tile with a `Bird` agent rule gets perches on its tree props' canopies and its buildings' roofs (`plan::canopy_perches`), capped by the rule's `max` (the oak tile's 12). The oak tile and the farm have one: the farm's 11 are `barn_red_b`'s finial over its cupola and ten points on its ridge cap 1 m apart (owner A1-Q3, `barn_red_b_perches_sit_on_its_roof`), so a farm drawing `barn_red` has none; the pine forest (`forest`) has none, so a world without an oak tile or a `barn_red_b` farm keeps every bird in the air. The oak's 12 perches are a table checked against the GLB's canopy shell (`oak_perches_sit_on_the_canopy`). An oak tile gains its roosts once its rise reaches the agents stage and its oak is drawn from the kit, so one still on its placeholder (its pack streaming) has none until the oak swaps in. Each oak tile runs a 36 s wave cycle from the moment its roosts appear: free birds, a whole free flock first, are sent to every perch and are pulled onto it within 8 s, sit until 22 s, then all launch together. A world that opens with oak tiles whose oaks are drawn (a loaded world, drawn at rest) opens with their birds perched. Bulldoze or undo removes the roosts and launches their birds; undo or redo brings them back on a fresh cycle. Scattered spruces on a tile with a `Bird` rule would share its cap with the hero (`roosts_with`); no shipped tile has both since the split.
- **Fish** swim in the water volume of connected water tiles. Regions are the water tiles joined across edges where the water continues (no cut face), and each region gets fish in proportion to its water tiles. Grouping follows each fish's spawn water (owner, 2026-10-14): a region's fish are shared between its river and spring tiles and its mouth, coast and ocean tiles by tile count, so a river chain joined to the sea through a mouth stays one region that fish swim across while its river fish keep their groups. Fish spawned in sea water are one school: each coheres and aligns with every such fish within 4 m. Of the fish spawned in river water 60% swim alone and the rest in groups of 2 to 5 (`plan::river_groups`, seeded from the world seed and the region): a fish coheres and aligns only with its own group, whose members spawn beside each other, and keeps 0.9 m clear of every fish. The same water (`plan::river_water`) picks the palette and the species (`plan::fish_species`): river and spring spawns are `fish_trout` in its river palette, mouth, coast and ocean spawns `fish_mackerel` (one palette), so a school never mixes species and a trout that swims through a mouth into the sea stays a trout. The trout's ocean palette is no longer drawn in play. The mackerel is the trout's length and sits inside its height, so the band below, built around the trout, holds for both. River water is murky, so river fish are made to read (owner, 2026-10-14): in river and spring water the band is its top 0.35 m (`plan::RIVER_BAND`) under a ceiling that keeps the fin 2 cm under the surface, the material lifts the river palette 1.5x in linear colour (its mean luminance to the ocean palette's) and the sea fish 2x (`SEA_LIFT`, owner A12-Q3: the mackerel's dark back read as a navy silhouette under the sea), and the compute pass grows a river-palette fish up to 30% larger (`plan::RIVER_GROW`, `anim.w`) wherever the band's ceiling leaves its larger fin under the surface, so it shrinks back to the trout's size on a mouth's skim water. `plan.rs` bakes a confinement band every metre from the water module's analytic bed (`water::tiles`, the bed contract in `docs/kit/water-contract.md`): fish centres stay 0.45 m above the bed and 0.25 m under the surface (plus the 0.4 m Gerstner amplitude where waves reach full height), at least 2 m from exposed water edges (the cut faces), and out of water too shallow for that band (the beach shelf, the river banks). Over a river mouth the fan shallows to 0.36 m, so there the band skims the surface instead (owner, 2026-10-14; the fan is not deepened): the trout's dorsal fin and belly each 2 cm clear of the surface and the bed (`plan::SKIM_GAP`), blending back to the usual band between 0.8 and 1.2 m of water, and open skim water holds the river channel's room (0.85 m) so the shore turn does not send fish back. Fish do not spawn in skim water (spawning needs a 0.3 m thick band). The compute pass integrates, refuses a step into a sample without room (the fish turns back up the room gradient), clamps height into the band and damps the climb where the band is under 0.5 m (a pitched 0.8 m trout would cross the surface); `plan::confine` mirrors that step and its test walks fish against the analytic bed. A fish whose water is bulldozed respawns in its region.
- **Rendering through water.** The boid material is opaque, out of the depth prepass and shadow passes, and its extension binds only the piece's `masks` texture (as the kit extension does) plus the boid storage buffer, so a boid pipeline samples the kit forward pipeline's count; every bird species and the fish share that layout. Fish draw in the opaque pass, which the refracting water's view transmission texture copies, so they show through the surface; the water absorbs them down to the bed beneath, not to their own depth.
- **Determinism.** Spawn points and launch headings derive from `--seed`, and the roost schedule from the boid clock, which sums the same clamped frame steps the GPU integrates (exactly 1/60 s per frame under `--clock fixed`). The published counts are therefore exact; GPU positions can differ in the last bits between runs because boids read neighbours the same pass is writing.

## Cache busting (web)

Every URL the web build fetches changes when, and only when, that file's bytes change (owner request 2026-10-14), so browsers and CDNs can cache every file but the page and never serve a stale one.

- **Versions.** `scripts/web/version-dist.mjs` runs as Trunk's `post_build` hook (`Trunk.toml`) on the staging dir, so `make build-web` and `make web-size` (the CI deploy) ship a versioned site; `trunk serve` runs the same build hooks. Each file's version is the first 10 hex digits of its SHA-256. Files keep their names: only the fetched URL gains `?v=<hash>`, so Bevy asset paths, the kit manifest's paths and `kit://` identities are unchanged, and a static host serves the file whatever the query.
- **References in built files.** Every quoted or `url()` reference to a site file in `*.html`, `*.css` and `*.webmanifest` is rewritten to `<ref>?v=<hash>`, and those files are hashed after their rewrite: `index.html` (the HUD's `hud.js` and `hud.css`, `web/wgsl-compat.js`, `web/frame-latency.js`, the favicons, the web manifest and the no-WebGPU redirect to `web/unsupported.html`), `web/unsupported.html` (its still, icon and the HUD stylesheet), `web/ui/hud.css` (the Manrope font) and `web/brand/site.webmanifest` (the app icons). A changed font therefore also changes `hud.css`'s version and `web/unsupported.html`'s.
- **The map.** Every file except `index.html`, `CNAME` and Trunk's own hashed outputs (`hex-world-<16 hex>.js` and `_bg.wasm`, already content-addressed by name) is listed with its hash in `window.__HEX_HASHES`, inlined into `index.html` as the first script in `<head>` (`<script id="hex-hashes">`), so the map is exactly as fresh as the HTML and costs no request (479 files on 2026-10-14: 30 KB, 6 KB gzipped). `index.html` itself is never versioned and must not be long-cached (GitHub Pages, which takes no custom headers, sent it with `Cache-Control: max-age=600` on 2026-10-14, so a deploy reaches a returning browser within 10 minutes).
- **The build id.** The same step hashes the map, Trunk's hashed file names and `index.html` (with the map script left out) into a 10-hex build id, inlined beside the map as `window.__HEX_BUILD` and written to `dist/version.json` as `{"id":"<id>"}`. It changes exactly when the site's bytes change, so an identical rebuild gives the same id, and `version.json` is never in the map, so a rerun stays byte-identical. The HUD polls it to offer a reload (see [New version available](#new-version-available)).
- **Runtime fetches.** The wasm's fetches go through `hex_assets::bevy`: the `kit://` source and, on the web, the default source (shaders) use Bevy's fetch reader with a request mapper that appends the version (`hex_assets::bevy::versioned`). The HUD uses `versioned(path)` from `web/ui/src/versioned.ts` for the audio manifest, every cue, the streamed music (`<audio>` `src`), the tile thumbnails and the loading layer's app icon. Native builds read files from disk and are unchanged.
- **Unversioned on purpose.** `index.html`, `version.json` (the HUD polls it with its own `?t=` query), the Trunk-hashed glue and wasm, `CNAME` (not fetched) and the absolute `og:image` URL in `index.html` (fetched by link-preview crawlers, not by the page). The kit manifest is compiled into the wasm, not fetched.
- **A file missing from the map** is fetched unversioned with one console warning per path (`assets: <path> has no content hash in window.__HEX_HASHES`; one warning in all when the page has no map), and `make web-smoke` fails on any unversioned or mismatched request.
- **Adding a fetched file.** Ship it in `dist/` (under `assets/`, which Trunk copies whole, or with a `data-trunk` copy link in `index.html`) and fetch it through the versioned path: from Rust, load it through the `kit://` or default asset source (nothing else to do); from the HUD, wrap the page-relative path in `versioned()`; from HTML, CSS or the web manifest, reference it by a relative or root path, which the post-build step rewrites. A new fetcher outside those (a new asset source, a raw `fetch` in another script) must append the version from `window.__HEX_HASHES` itself. `node --test scripts/web/version-dist.test.mjs` (part of `make ui-test`) checks deterministic hashes, that one changed file changes only its own version and its referrers', that a rerun is a no-op, and that the build id matches between `index.html` and `version.json`, survives a rerun and a separate build, and changes with any asset, Trunk output or the page.

| `make kit-compress-test` | Local. The `kit-compress` and `kit-provenance` node tests |
| `make kit-renders PIECE=<id>` | Local. Blender socket round-trip check, then the six-view JPEG evidence into `assets-source/kit/<id>/renders/` |
| `make kit-provenance PIECE=<id> REFS=assets-source/refs/<ref> [ROUTE=interactive]` | Local. Writes `assets-source/kit/<id>/provenance.json`, runs the gate and the renders, then stamps `validation.pass` |
| `make kit-material-provenance SET=<set>` | Writes and validates `assets-source/kit/materials/<set>/provenance.json` |
| `make kit-check` | The Rust kit gate alone (`cargo test -p hex-render --test kit_gate`); `make test` runs it too |
| `make kit-fixture` | Local. Rebuilds the committed gate fixture and re-syncs the served copy in `assets/kit/p1/fixture/` |
| `make fetch-hdri` | Downloads the gitignored look-dev HDRI into `assets-source/hdri/` and verifies the SHA-256 in `assets-source/lookdev/lookdev.json` |
