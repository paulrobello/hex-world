# Hex World Blender asset pipeline

You author ONE kit piece (or one tileable material set). Read `references/stages.md` before touching Blender, and read `references/pitfalls.md` before your first bake.

This skill is project-level for now and a later card promotes it to user level. The rules below are the portable pipeline. Everything specific to Hex World (frame, constants, seam rules, texture channels, budgets, paths and make targets) lives in **`references/project.md`**, and you must read it too.

## Rules
- **Reference first.** Modeling starts only after the owner has approved the Higgsfield reference images for the piece (`make refs PIECE=<id>`, then the owner's `approval.json`). No approved reference, no high-poly.
- **Effort.** Every Blender asset subagent is dispatched at high effort (owner, 2026-10-13). In Claude Code, pass `effort: "high"` on the `Agent` call.
- **Concurrency.** At most 3 Blender asset subagents run at once (PRD §11.1). Own exactly one piece id. Use a scene and collection named after it, and the staging dir `target/kit-stage/<piece>/`.
- **One writer for shared files.** When asset agents run in parallel, each touches only its own generator, its `_<family>.py`, `assets-source/kit/<id>/` and `assets/kit/p1/<id>/`, and runs build, compress, determinism and renders. The orchestrator owns `assets/kit/manifest.json`, `data/pending-pieces.ron`, `data/tiles/*`, `crates/**` (the kit gate, the `kit_scene.rs` layout, `scatter.rs`, `boids/plan.rs`, `walk.rs`) and this skill's files, and runs provenance and `make kit-check` after landing them. Hand back the manifest entry, the layout placement, any gate change and any proposed skill text in your report. An agent working alone may do all of it itself. (Review 2026-10-14: 20 rebase conflicts in 6 parallel runs in exactly these files; the river-mouth sub-briefs with this split finished in 11 and 31 minutes with none.)
- **A new kind of piece needs its gate branch first.** Before modeling a piece unlike any in the manifest (a new kind, a ring off y = 0, a centre with no lanes, a second mesh per LOD, a slot under water, a prop over its kind budget), list the `kit_gate` checks it will hit (`references/gates.md`) and plan the additive gate change and its failing test before the build. Under the one-writer rule, report the needed change to the orchestrator instead of editing `kit_gate.rs` alongside siblings.
- **Invocation.** Always `make kit-build PIECE=<id>`, or `"$BLENDER" -b --factory-startup --python-exit-code 1 -P …`. Blender exits 0 on tracebacks without the flag.
- **Worktree sessions.** A worktree-isolation hook refuses any command line it cannot fully verify, and each refusal costs a turn (144 refusals across 28 runs before this rule was rewritten). Write lines it accepts:
  - Run each git command alone in its own call, with nothing else on the line: no `;`, `|`, `>`, `echo` or `$?`. Read the exit code from the tool result. `git add … && git commit …` passes. Never point git at the main checkout (`git -C <main>`, `cd <main> && git`).
  - Spell every program, script path and option literally. A shell variable or `$(…)` in those positions is refused (`S=…; python3 $S/x.py`, `sed -n "$(grep …)p"`, `$PWD/…`, `for p in …; do make PIECE=$p …`). Loops and `until` polls whose commands are all literal pass.
  - Never source a file: `. tools/ktx-env.sh` is always refused. `make kit-compress` and `make kit-material` find `ktx` themselves; to run it by hand see `references/project.md`, "Tools and pins".
  - Write scripts, patches, shot JSON and multi-line content with the Write or Edit tool, then run each as one plain command (`python3 /abs/x.py`, `bash /abs/run.sh`). Heredocs, `python3 -`, long `node -e`, and `magick` with parenthesised sub-images or `%[fx:mean]` inside a compound line are refused (use a small PIL script).
  - Edit the worktree copy of a file, never its main-checkout path. The session scratchpad is shared with sibling agents, so keep scratch files under `<scratchpad>/<piece>-<pass>/`, never a generic `before/`.
- **Helpers.** Import helpers from `scripts/blender/lib/` (contracts in `references/lib-contracts.md`). Do not re-implement the frame math, the border ring, bakes or export. Real piece generators never import the `tests` package. Shared per-family code (`kit/_<family>.py`) is fine: provenance hashes it as `generatorDeps`.
- **Frame, pivot, seams, textures and budgets.** Follow `references/project.md` exactly. In short: Blender (x, y, z) exports as runtime (x, z, -y), the pivot is the hex center (trees: the trunk base), border-touching pieces are never decimated, and the GLB embeds no images.
- **Provenance.**
  - Every piece has `assets-source/kit/<piece>/provenance.json` and every set `assets-source/kit/materials/<set>/provenance.json` (`references/provenance.md`), with `authoringAgent = {"harness": "claude-code", "model": "claude-opus-5-5"}`.
  - `generator` and `generatorDeps` are mandatory and re-hashed by the gate. Once a piece is approved, editing its generator or a `_*.py` helper (even a comment) fails `make kit-check` until it is rebuilt and re-approved.
  - `.blend` files and bake intermediates live only in the main checkout's blend store, `assets-source/blend/<piece>/` (gitignored). Record each one's SHA-256. External `.blend` storage is deferred: do not upload them anywhere or build an upload step.
- **Timing.** Every timing measurement (bake time, build time, frame time) runs with host load ≤ 15 before and after, checked through `e2e/perf-load.mjs` (a module: wrap the run in its `guarded()` or call `waitForLoad()`; `node e2e/perf-load.mjs` on its own prints nothing and checks nothing) or with `uptime` before and after. A number taken outside that window is not reported. Build first and guard only the measured run: a wasm rebuild alone can push the load from 14 to 50. Screenshots, thumbnails and owner-review shots are not timing measurements, so do not wait on host load for them: run them under `caffeinate -d -u`, check every PNG's mean (a black frame is about 26 KB with mean 0), re-run a black or timed-out run once, and note the host load in the report. (Review 2026-10-14: load waits on shots cost about 1.5-2 hours across 6 runs, and most timed out and ran at load 30-290 anyway.)
- **Self-review before the owner.** Judge a tileable set from its 2×2 tile at 1:1 before compressing, and a piece from stills against its approved reference. Read the numbers too (AO mean and p05, alpha coverage per mip, texel density per slot), not just the image.
- **Owner checkpoints use one review sheet.** Present image files, never a text description. Before asking for review, build one sheet per piece in `docs/checkpoints/<piece>/` (JPEG, with its committed shot script): the approved reference; a textured headless EEVEE still (the 6-view render is untextured); and in engine with `--tilt off`: play distance, a seam with each neighbour kind it meets, a 3-8 m close-up on the sun side and on the shade side, eye level at 1.7 m (walk mode), and a scale shot beside a house or the oak. Re-take the sheet after the final rebuild, so it never shows a superseded mesh or layout, and never leave review shots only in gitignored `target/`. (Review 2026-10-14: most owner redos, from the oak's six rounds to the cattail detail and the river-mouth colour line, were visible in one of these views that nobody shot.)
- **Done.** You are done when `make kit-check` passes and the 6-view render plus the in-engine shot exist. Owner approval is recorded by the controller. Never record it yourself.
- **Friction.** Log every snag in `assets-source/kit/<piece>/friction.md` (what happened, the fix, the minutes lost). Fold each one into this skill (a rule, a stage command or a pitfall), or note in the entry why no change is needed. When sibling asset agents run in parallel, write the proposed skill text in `friction.md` and your report instead, and the orchestrator folds it in the same session.

## Stage order
approved reference → high-poly → LOD0 + UVs → bake → LODs + collider → sockets + export → compress → gate → provenance → owner review. Commands for each stage are in `references/stages.md`. Hero pieces take the interactive route for the high-poly only (`references/stages.md`, "Interactive route").
