# Provenance

Every piece has `assets-source/kit/<piece>/provenance.json`, written by `make kit-provenance PIECE=<id>`. Field list from research brief §(d), which merges PRD §11.4 with `~/Repos/par-factory/docs/specs/09-asset-pipeline.md` §4 and the real par-factory records:

`pieceId`, `version`, `route` (`scripted`|`interactive`), `generator` {`path`, `sha256`} plus `generatorDeps` [{`path`, `sha256`}] (local `_*.py` helpers the generator imports), plus for `interactive` pieces `blendRef` {`store`, `key` (store-relative, e.g. `<id>/<id>_high.blend`), `sha256`, `bytes`} (the export stage stays hashed as `generator`), `authoringAgent` {`harness`, `model`}, `blender` (`version_string`), `toolVersions` {`gltfTransform`, `meshoptimizer`, `ktxSoftware`, `node`}, `bake` {`device`, `samples`, `cageExtrusionM`, `maxRayDistanceM`, `marginPx`, `receiverSignature`, `channels{name: {size, colorspace, sha256}}`}, `lods` [{`lod`, `tris`, `ratio`}], `collider` {`node`}, `sockets` [{`name`, `position`, `yaw`, `extras`}], `pivot`, `texelDensityPxPerM` {`min`, `median`, `max`} (or, for multi-material pieces such as the tree, one such object per material slot), `compression` {`meshopt`, `budgets` {`class`, `ktxMax`, `ktxBytes`, `glbBytes`}, `textureEncodes[{channel, family, format, transfer, sha256, bytes}]`}, `derivedFiles` [{`path`, `sha256`, `bytes`}], `references` [{`path`, `sha256`, `sourceSha256`, `provider`: `higgsfield`, `model`, `jobId`, `prompt`}] (copied from `refs.json`), `license`, `validation` {`pass`, `date`, `checks[]`}, `approvals` [{`who`, `when`, `gate`, …}]. As in par-factory spec 09 §4, a piece with missing provenance or a failing validation must not enter `manifest.json`.

Missing provenance, `validation.pass != true`, or a `derivedFiles` hash that does not match the file on disk fails `make kit-check`.

`generator` and `generatorDeps` are mandatory for every piece and tileable set, whatever the route. The gate re-hashes the generator and every helper, and requires `generatorDeps` to list exactly the `_*.py` siblings the generator imports (transitively); `scripts/blender/lib/` is out of scope. The assembler takes both from the build report (`export-report.json`, or a set's `bake-report.json`) and refuses when the report lacks `generatorDeps` or a file changed since the build. An interactive piece must carry `blendRef`, and its `sha256` must equal the bake report's `blend.sha256`.

## Fixed values (Hex World)
- `authoringAgent` is `{"harness": "claude-code", "model": "claude-opus-5-5"}` (R3).
- `blendRef.store` is local: the `.blend` lives in the gitignored `assets-source/blend/<piece>/` of the main checkout (the blend store, `project.md`) and only its SHA-256 and byte count are committed (R1). External storage is deferred.
- `approvals` entries are written by the controller after the owner reviews screenshots. An authoring agent never writes an approval. When an authoring agent re-exports an approved piece (new sockets, a fix), it appends one entry with `"status": "pending"`, the same `gate`, a short `revision` and `notes` naming what changed and which stills to review, and leaves the earlier approval in place as history. The controller replaces the pending entry with the approval. The gate reads only `gate: "reference"` entries, so a pending entry neither counts as nor blocks an approval.
- `approvals[0]` is the owner's reference approval: `make kit-provenance PIECE=<id> REFS=assets-source/refs/<ref-id>` copies `<ref-id>/approval.json` (`gate: "reference"`) ahead of the piece's own `assets-source/kit/<id>/approvals.json`, and refuses to run when that `approval.json` is missing (R2).
- Every `textureEncodes` entry, PNG included, carries its channel's `transfer` (albedo and emissive `srgb`, normal, orm and masks `linear`). The assembler refuses a mismatch, because the PNG file itself carries no color space and the runtime loads it by this record.
- `make kit-check` also fails when a reference file's hash differs from `references[].sha256`, and, for pieces in `assets/kit/manifest.json`, when `references` is empty or no `gate: "reference"` approval lists one of them.
