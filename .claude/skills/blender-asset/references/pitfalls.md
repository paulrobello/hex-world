# Pitfalls

Known Blender, bake, export and KTX2 traps, from the asset-pipeline research and the P1 friction logs (`assets-source/kit/*/friction.md`).

## Blender and its API
- **Blender exits 0 on script errors.** Always pass `--python-exit-code 1` (external vault note `Tools/blender-script-failures-exit-zero.md`, external local guide `~/.claude/guides/blender-mcp.md`).
- **Blender 5.2 API drift.**
  - Use `BLENDER_EEVEE`, not `BLENDER_EEVEE_NEXT`.
  - Leave `export_loglevel` unset.
  - An empty RNA enum list does not mean a format is missing.
  - Principled inputs are named `Emission Color` and `Coat Weight`.
  - Sharp edges use `set_sharp_from_angle`.
  - SCENE-mode animation export needs `use_active_scene=True`.
  - Verified against 5.2.2 LTS (2026-10-13): `delaunay_2d_cdt(coords, edges, faces, output_type, epsilon, need_ids=True, /)` with output_type 1 = triangles inside the constraints; `MeshPolygon.use_smooth`, `Mesh.normals_split_custom_set_from_vertices` and `Mesh.corner_normals` exist; glTF `export_image_format` accepts `NONE`, and `export_tangents`, `export_texcoords`, `export_normals`, `use_active_scene`, `export_extras` exist; bake types include AO, NORMAL, ROUGHNESS and EMIT; `kernel_optimization_level` exists on the Cycles prefs.
  - `Material.use_nodes` is deprecated (removed in 6.0) and warns on access. New materials already have a node tree with a Principled BSDF, so use `lib.materials.ensure_nodes(mat)` instead of setting `use_nodes`.
  - Further 5.x renames beyond this list have not been checked.
- **`matrix_world` is stale for objects created in the same script** until `bpy.context.view_layer.update()`. A socket empty read back before an update reports position (0, 0, 0). `export.write_export_report` updates the view layer first.
- **Removed objects linger in `view_layer.objects` as `None`.** After `bpy.data.objects.remove` on a freshly opened file, iterating the view layer (for example `scene.select_only`) hits a `None` base. Call `bpy.context.view_layer.update()` after removals.
- **Renders embed the wall-clock date.** Blender writes Date and RenderTime metadata into every PNG and JPEG, so re-renders of identical pixels differ in bytes. `gate.render_six_views` turns `use_stamp_date` and `use_stamp_render_time` off; do the same for any committed render.
- **A copied `target/` can embed another checkout's data files.** `hex-core` compiles `data/tiles/*.ron` and `data/pending-pieces.ron` in with `include_str!`, and a cache copied from the main checkout can carry those files as they were in whichever checkout last built it, so cargo does not rebuild it when the worktree's copies change: the data validator then reports a stale pending list ("ocean_base is in assets/kit/manifest.json: remove it from data/pending-pieces.ron" with the line already removed). Run `cargo clean -p hex-core` after editing `data/` in a worktree whose `target/` was copied. The same staleness reaches main: `hex-assets` tests read `env!("CARGO_MANIFEST_DIR")` fixtures, so after a worktree's build is merged or copied back, `make checkall` in main can fail `meshopt_glb` with `NotFound` on a removed `.claude/worktrees/agent-*` path (2026-10-19). `cargo clean -p hex-assets -p hex-core` fixes it; it is not a code failure.
- **Removing faces while iterating a set of BMFaces breaks determinism.** `_house_longhouse.box` (and `_house.Mesh.box`) drop a box's buried faces while iterating `{f for v in res["verts"] for f in v.link_faces}`. BMFace hashes follow memory addresses, so the removal order, and with it the order in which later faces refill the freed slots, can change between runs: `well_stone`'s 72 stone boxes exported a different LOD0 index buffer on each run (`make kit-determinism`: "GLB differs" on one `indices` bufferView, with positions and UVs identical; 2026-10-20). Build boxes face by face in a fixed order (`_house_well.box`), or sort the faces before removing them; the well was deterministic after that change alone. With far fewer such boxes, `house_twostorey_c` (`lh.box`) and `house_cottage` (`_house.Mesh.box`) were deterministic in `make kit-determinism` on 2026-10-20, but nothing guarantees it.
- **Never run two `make kit-determinism` at once.** Every run shares `target/kit-det/{a,b}` and starts with `rm -rf`, so a parallel run deletes the other's output and it fails with "GLB differs" on a missing file. Run them one at a time.
- **`make blender-test` is local only.** CI has no Blender, so never add it to `checkall`. Anything checked against committed files belongs in the Rust gate (`make test`).

## Cycles bakes
- A diffuse pass darkens base color, so bake base color and metallic through EMIT (`lib.bake.bake_emit_input`).
- Triangulate before baking so the bake tangents and the exported tangents agree.
- Set `use_clear` only on the first group. Keep `use_pass_direct` and `use_pass_indirect` off.
- Image colorspace must be sRGB for base color and emission and Non-Color for everything else.
- Metal kernels recompile per channel, so `kernel_optimization_level = "OFF"`. The bake device defaults to CPU; `lib.bake.setup_cycles` reads `HEXW_BAKE_DEVICE`.
- `margin=0` leaves no gutter and mips bleed. Use about 8-12 px, with two masks where preservation matters (external vault note `Patterns/bounded-gutter-texture-bake-preservation.md`). Tileable sets are the exception: a wrapping tile has no gutter.
- **Other meshes darken AO bakes.** A mesh 0.4 m above the cap took the fixture's AO from about 1.0 to 0.001. `lib.bake.bake_to` hides every mesh that is neither `low` nor in `highs` for the bake, so LOD1/LOD2 and colliders may exist before baking. Do not bypass `bake_to` with a raw `bpy.ops.object.bake`.
- **Set the world AO distance before an AO bake.** The default is 10 m, so on a tree every limb and strand above darkened the bark (mean 0.55, a quarter of texels at 0). Set `scene.world.light_settings.distance` to the scale of the local relief (the oak: 0.35 m bark, 0.3 m canopy shell) and record it as `aoDistanceM` in the bake report. `scene.reset_scene` leaves no world, so a scripted piece creates one first (`scn.world = scn.world or bpy.data.worlds.new(piece)`); the oak gets its world from its `.blend`.
- **Buried receiver faces bake to 0.** Faces inside other geometry (intertwined trunk strands, root and limb starts) have no sky. Delete them from the receiver before the bake (`_tree.cull_buried`, `cull_inside_crown`).
- **Re-derive cage and ray per piece and per relief.** The machine-scale cage 0.055 m and max ray 0.14 m do not carry over. The oak's 0.07 m bark relief needed cage 0.25 m and max ray 0.5 m: at cage 0.12 m 2.0% of texels missed, at 0.2 m 0.02%. Sweep a few values on a small diagnostic bake and read mean, p05 and miss rate, not just the image.
- **A bake source needs a solid backing.** A high-poly made only of leaf cards lets rays through the gaps, which bake to 0 (black holes). Put a solid, dark surface just under the leaves (the oak's dome at 0.97 R).
- **Bake normals against the smooth surface.** Baking tangent normals against a low-poly's interpolated normals encodes its facets, which reappear when the runtime normals change. Set the receiver's custom normals to the smooth shape's normals first (`_tree.shell_smooth_normals`).
- **`bake_emit_input` takes `highs` once.** Its first four parameters are positional-only; `highs` in `**kw` raises a clear `TypeError`.
- **A shared masks map with a partial AO bake.** An AO bake writes only the receiver's islands and their gutter, so every other texel of the image keeps the clear value, A = 0 (river_road_bridge_center: mean A 31/255 over a map baked on the road alone). Binding another slot to that map multiplies its diffuse light by 0 even at the MVP values, because the masked path applies masks.A unconditionally. Before setting `"masks": true` on a slot of a piece that already has a map, read the map at that slot's UV0 (`cargo test -p hex-render --test kit_gate print_hook_matrix -- --ignored --nocapture` gives the max per slot; sample A as well) and write the slot's values, A included, over its own texels after the bake, never over the receiver's (`_river_bridge.dress_masks` asserts the two footprints miss each other). Its own texels are not enough: the box-filtered mips blend the A = 0 background back in (the bridge dressing fell to A 0.52 at mip 4), so also fill a halo of the slot's values around it (32 px there), kept clear of the receiver's baked texels by at least 2^k - 1 texels (11 there) so the receiver's mips 0 to k stay unchanged. Check A per slot on box-downsampled copies, not only at mip 0.
- **Colour-only props get masks without changing their look.** A colour-only slot had no AO, so its masks carry A = 1 and the MVP render stays pixel-identical. When the piece already has a planar UV0 (`uv.planar_cap_uv`), write R, G and B as an analytic field of (x, y) with numpy (`_beach_dress.masks_field`, `_river_dress.masks_field`): no Cycles bake, and the rebuilt GLB stays byte-identical. A slot that is always under water takes R 0 and G 0 and joins the gate's `SUBMERGED` list (ocean_center's stones).
- **A unique masks bake spends texels on every face, seen or not.** Leave out faces nobody can see (plinth tops under a floor, wall behind a door leaf, end caps behind bargeboards, soffit over the interior) before the unwrap (`barn_red.py`, 2026-10-19).
- **At house-scale masks densities (13-18 px/m) a face under about 8 cm bakes no texel.** Its UV centroid samples A = 0 and R = 0, so it draws black and takes no snow; the hooks gate checks a slot's maximum, so it misses this. Sample masks at every LOD face's UV centroid on the reimported GLB and fill unbaked texels under faces from the slot's hooks and median AO (`barn_red.fill_unbaked`). `_house.build_piece` runs the fill and asserts 0 unbaked triangles per LOD (house_cottage had 74/22, house_twostorey 86/36, before 2026-10-19); `docs/checkpoints/houses-masks-fill/masks_centroids.mjs` checks a compressed GLB.
- **On a building with many thin members, the island margin sets the masks density, not the surface area.** At 1024², `island_margin` 0.012 left the bakery's walls at 8.7 px/m; 0.006 with a 2 px bake margin gave 20.7. Keep the island gap at least 2 × bake margin + 2 px (`bakery_shop.py`, 2026-10-19). A smaller gap buys density at mip 0 and costs it at mips 2-3, where the unwritten background bleeds in sooner: on the houses 6 px raised density 22% but darkened thin members by up to 0.08 AO at mip 3, so the houses keep the default pack. Judge a margin change on box-filtered mips, area-weighted per slot.
- **Detail behind glass is colour, not AO.** masks.A only scales ambient light, so A-only goods vanish on the sun side; give them colour bands on their own slots plus an authored A/B pattern (`bakery_shop` bread).
- **Overlapping decals join after the bake.** Road paint 3.5 cm above the bed shares the bed's planar UV0, so a joined AO bake writes both into the same masks texels and darkens the dashes. Bake AO on the bed alone, then join the paint into each LOD. The same holds for any surface stacked over another under a planar UV: house_pad's gravel under the driveway and under the doorsteps baked AO 0 into the texels of the surfaces on top (yard p05 = 0). Do not build buried faces (stop the lower surface where the upper one starts), and join small stacked parts (doorsteps) after the bake.

## Tileable sets
- **Only 4D textures wrap.** `materials.torus_coords` wraps only when every texture is 4D Noise, Voronoi or White Noise with W linked. A 3D texture ignores W and mirrors the tile about its middle, which the 2×2 seam test does not show. Wave, Magic, Brick, Gradient and Checker cannot wrap.
- **Low-frequency 4D noise mirrors the tile.** At a scale near the torus size the noise barely varies along the sin component, so the tile correlates with its own mirror (0.16-0.18 read as kaleidoscope patches). Keep every feature scale ≥ 4 on a tileM 2 set, and check the mirror correlation as well as the wrap edges.
- **A sliced 4D Voronoi F1 reads as polka dots.** The torus surface cuts 4D cells off-centre, so F1 distance thresholds give sparse round discs, and the cells come out about 5x larger than 1 / scale suggests. For packed stones (gravel), shape them from `DISTANCE_TO_EDGE` and colour them from an F1 node with the same scale (same cells); measure the stone size on the 2×2 tile (gravel: Voronoi 40 is about 2 cm).
- **Judge the 2×2 tile at 1:1 before compressing.** Tight Voronoi tuft cells read as polka dots at 512 px/m. Voronoi suits sparse features (clover, pebbles); turf needs soft, high-distortion noise blades.
- **Vertically profiled sets** (the soil cutaway) must line their profile up with the wall mapping (`project.md`, "Textures").
- **Sets made of shapes (leaf litter, pebbles) draw better in numpy.** `kit/mat_litter.py` stamps every element with wrap-around indices and builds noise as FFT band-limited white noise, so the tile is periodic by construction (mirror correlation about 0.02) and writes the maps with `bake.write_png`. Judge it tiled 8x8 at game scale as well as the 2x2 at 1:1: elements pasted on top of everything (moss blobs) read as camouflage, so lay soft cover as a ground layer the elements partly cover.
- **A rim-only feature on a tileM 4 wall (a grass lip) must not move the rim row.** The rim and the foot are the same texture row, so jittering the whole band coordinate pushes lip colour onto the foot (or foot colour above the lip). Measure depth below the rim exactly (`t = fract(-atan2(w, z) / 2π)`, top PNG row = rim) and jitter only the lip's lower edge (`mat_soil.py`, `grass_lip`).
- **Previewing a replacement set in engine needs no code or manifest change.** Native runs load `cwd/assets`, so clone `assets/` into a scratch dir (`cp -cR`), overwrite the set's `png`/`bc7.ktx2`/`astc.ktx2` files there and run the binary with that cwd (`docs/checkpoints/skirt-options/run.py`). Compress into `target/` with `kit-compress.mjs material <set> --stage … --out … --report …`; the defaults write into `assets/` and `assets-source/`. Native shots taken while a Blender bake held the GPU, or at host load near 100, came out all black (about 26 KB each): check shot sizes and retry (`run.py` does).

## Biome bases
- **A biome cap must be grass at the border.** Tileable layers sample in world space, so a slot change at the hex border (a tint or another set) is a straight line against the meadow. Split one cap mesh into slots per face along wavy contours inside the rim (`kit/forest_base.py`: untinted `grass` rim identical to `meadow_base_cap`, a tinted transition band, then the biome set), give each contour its own CDT points in every LOD (drop lattice points within about half a spacing of it, or the boundary zigzags), and assert that every border-touching cap face is the rim slot. Two such bases side by side then show a grass strip between their floors; the fix is a socket-chosen edge piece (PRD §6), not the base.
- **An overlay edge piece over a base that is not 60-degree symmetric needs one variant per local edge.** A piece rotated to every edge lies over each of the base's six wedges, and forest_base's contours and relief differ under each: one piece lifted over the highest of the six caps floated up to 0.18 m over the litter (a visible hump). Build `<piece>_e<k>` per local edge from one helper (`kit/_forest_edge.py`): rebuild the base's LOD caps (check the copy against the base's committed `receiverSignature`), rotate cap k onto edge 0, clip it to the slice with `bmesh.ops.bisect_plane` and lift it 2 cm, so it follows the cap exactly in every LOD and adjacent variants meet exactly on the shared ray. Keep the border section identical in every variant. A clipped cap keeps the base's ring and contours, so LOD2 can exceed 15% of the clipped LOD0: split LOD0's longest interior edges (exact on flat triangles, never the border ring) until the ratios hold.
- **Staging an approved base for a mock dirties its committed reports.** `make kit-build PIECE=<id>` also copies `bake-report.json` and `export-report.json` into `assets-source/kit/<id>/`; `git checkout` them after a skip-bake staging build.

## Leaves, foliage and LODs
- **Alpha coverage below 0.5 collapses with mips.** A 4D Voronoi sliced at a fixed W gave sparse round blobs (11% opaque), and the alphaCutoff 0.5 canopy vanished from mip 7 on. Keep leaf-strip coverage at or above about 0.55 at mip 0 and measure it per mip (`gates.md`).
- **Shader nodes cannot draw a lobed leaf.** Draw leaf tiles in numpy (`_leaves.py`: lobed outline, midrib, per-leaf tone, folded normal) and write them straight into the atlas strip; the live session loads the same arrays so the showcase and the engine match.
- **Grass-tuft coverage sits near 0.5, and that is fine if it is stable.** Side-view tufts with a sod band at the root measure 0.46-0.53, and top-view flower rosettes about 0.35 (their disc footprint caps them near 0.6). What matters is that coverage holds down the chain: clumped masks stay within ±0.05 to the 4×4 mip, while thin isolated blades vanish. Measure each tile, not the atlas average (`wildflower_clump` bake report, `alphaCoverageByMip`).
- **Flat horizontal cards streak at a low camera.** A rosette card seen nearly edge-on stretches into horizontal smears. Tilt it outward along the clump's dome and seat it inside the tufts, and sink every vertical card's bottom edge below the ground (`wildflower_clump`: 0.07 m).
- **Draw a tall card's tile at the card's aspect, and size plants against the play grass.** A square 256 px tile on a 0.24 x 0.5 m single-stem card stretched every flower head into a vertical sliver, and 0.3-0.55 m stems disappeared in the meadow grass (blades about 0.35 m, up to 0.7 m with clump noise; `play/grass.rs` `style`). `wildflower_single` draws its side views on 128 x 512 px tiles with both axes in card widths (`_single._canvas`), so heads stay round, and stands 0.7-0.95 m tall. Check a new plant in an eye-level and an orbit play shot, not only in Blender.
- **Adding a part to a coarser LOD of an approved atlas piece: never before the unwrap.** The atlas pieces unwrap every LOD together and pack once, so a new LOD1 face moves LOD0's islands and re-bakes its masks. Copy LOD0's faces in after the bake with `_lod_copy.copy_faces` (it skips faces the target LOD already has), or put a new face's UVs on one baked texel of the part it stands for, then check in the staged GLB that LOD0's primitives are byte-identical (LOD1 pass, 2026-10-25).
- **A masks coverage sampler tests G, not A.** Baked AO (A) can be 0 in a fully occluded texel; every slot's porosity (G) is at least 0.05, so G = 0 marks an unbaked texel.
- **Leaf cards decimate badly.** Build LOD1/LOD2 from a card subset scaled up to hold coverage (`card_subset`), and decimate only the bark.
- **Conifer fronds (`kit/_forest.py`).** Thin needles alone measure about 0.27 coverage: draw a shadowed frond body (alpha 1) under the needles to hold 0.55+ down the chain. A card-only crown reads as plates around sky: put a small, near-black inner cone (a colour + masks slot, no texture, so no texel-density cost) inside it, and fold the cards so their sides hang. Regenerate LODs from the branch list with fewer segments, but keep at least 2 segments per card: with only root and tip rows the fringe's median wind U lands on the boundary between the trunk's sway and 1.
- **Normals in a card's plane give zero tangents.** MikkTSpace returns a zero tangent, and so do zero-area (collinear) faces; `export_glb` now fails `make kit-build` on it, naming the mesh and primitive (it used to surface as `ACCESSOR_VECTOR3_NON_UNIT` in `kit-compress`). Blend part of the card's face normal back into authored foliage normals (`project.md`, "Foliage normals").
- **Unweighted per-face medians are skewed by face count.** `uv.measure_texel_density` takes an unweighted per-face median, so many small leaf cards hid bark at 108 px/m behind a 270 px/m pooled median. The gate is per material for this reason; still read per-slot numbers when tuning.
- **Small or distant pieces: fill the whole atlas, not a fixed gutter.** Boids are drawn a few dozen px long and sample deep mips, where a black background behind a 6 px gutter averages into every island edge: the first `bird_starling` albedo lost 9% of its island luma at 16² (box filter) and `fish_trout` 11%. Filling every texel from its nearest island (`_fauna.fill_index`, bounded to its half on a split atlas) holds both within 1%.
- **Colour-only foliage (reed blades) is single-sided, and its callers set its shading.** A slot without `alphaCutoff` is culled single-sided, so every blade needs a back sheet on its own vertices: a V upper side plus a flat back sheet costs 6 tris per segment, a V on both sides 8. A clump of two V blades, seven flat two-segment blades and three cattails (31 tris each: stalk 6, head 22, spike 3) costs about 170 tris, so ten clumps beside 560 tris of stones need more than a prop's 1,500: the river dressing prop `river_spring_center` has 2,500 (owner, 2026-10-14; `kit_gate` `RIVER_DRESSING_LOD0_MAX`, `_river_dress.LOD0_MAX`). The dressing generators set `f.smooth` on every face after the helpers run, so set it only on your own slots' faces, or a helper's smooth shading and sharp midrib edges are wiped. A part that needs a slot outside the caller's face-index range (the cattail's pale spike in `river_stone`) carries a bmesh int layer and is moved after the range pass (`_river_dress.retag_spikes`).
- Never decimate a border-ring piece; regenerate it.
- **Place dome rings by normal angle, not latitude.** A flattened dome (the oak's underside is 0.4 R deep and 1.15 R wide) turns 90 degrees within 0.3 m of its rim, so rings at even latitudes left 46-48 degree corners at the rim and 17-20 degree steps on top. Rings at equal steps of the normal elevation psi (latitude = atan(b/a * tan psi)) give an even step everywhere for the same triangles, and columns can taper toward the poles by cos(psi) (`_oak.SHELL_RINGS`).
- **The shell's smart-project angle moves the canopy density.** Re-topologising the oak sector moved the canopy median from 267 to 250 px/m (gate 256) at the lib's 1.152 rad; sweeping 0.6-1.5 rad gave 215-259. Re-check the per-material median after any shell topology change. Since the size pass the oak unwraps its sector as one island (`bpy.ops.uv.unwrap(method="MINIMUM_STRETCH")`, seams only on the two meridians), which packs to 0.44 of the atlas against smart project's 0.27-0.38 (`SHELL_UNWRAP`).
- **Scaling a baked piece up drops every unique density by the scale.** A 2048² cap leaves no larger map, so 1.2x took the oak canopy from 258.7 to 216 px/m (gate 256). Win the atlas area back before scaling: unwrap the shared sector as one island (above), narrow the bark column (uvPerM 1/36 -> 1/54; the bark set keeps 512 px/m through `tileUvScale` = scale / (uvPerM x tileM), only the masks AO density drops), and probe the packing headless on the sector alone before a full build. Build and bake at 1x and scale every LOD and the collider just before export, re-setting each corner normal (`SCALE` in `tree_hero_oak.py`); measure densities at the exported scale. Never scale the GLB root node: the gate reads raw primitive positions.
- **One large island packed around many locked islands can overrun the strip.** Blender's packer put the single shell island over the whole unit square (v max 0.992) at every bark column with the ~70 bark islands locked. Pack it against one placeholder rectangle over the bark column instead (`pack_below_strip(left=...)`), and try each column with both packs.
- **Branch starts at one height read as a collar.** The oak's eight roots all started at z 1.6 m with radius 0.7 next to a 0.95 m strand bundle, so their start rings and up-facing caps formed a lit ledge around the trunk (owner, 2026-10-14). Start each root on its parent strand's centreline, thinner than the strand's inscribed receiver tube, so `cull_buried` removes the ring and cap; spread the start heights per branch (one height still left a ring of root tops where they exit); let the root run down along the strand first (an outward power above 1) for a concave flare. Shade the remaining tube intersections with the smooth union's gradient on vertices within the blend radius of a second branch (`_oak.junction_normals`).
- **A tube's UV V must stay common to a ring.** V along each column by its own edge lengths (to undo bend stretch) accumulates a different V per column, so ring edges slant in UV and the stretch grows (oak flare anisotropy p95 4.5, max 55). Advance a ring's V by the mean of its column edge lengths and step U by the chord 2 r sin(pi / n), not the arc (`_oak.metric_tube_uv`: p95 3.07 -> 1.59). A long ring step on a tapering, bending root is what stretched the P3 bark; measure the anisotropy per triangle (`uv_stretch` in `tree_hero_oak.py`), not by eye.
- **A dark dielectric under the leaves reads as a grey sheen, whatever its albedo.** The oak shell's ORM.G was a flat 0.62 fill, so the near-black dome between its baked leaves (linear luma 0.032) showed sky specular (F0 0.04, Fresnel at grazing) brighter than its diffuse: pale grey-green plastic in play (owner, 2026-10-14). Darkening the albedo alone makes the grey share bigger. Mask the gap texels from the baked albedo (`tree_hero_oak.py` `GAP_*`: distance to the under tone, ramped so leaf texels stay byte-identical), give them roughness 1.0 and a darker albedo. Roughness 1 still leaves about F0 x 0.45 of sky, so `kit_material.wesl` fades F0 to 0 on unique foliage above roughness 0.95 (Bevy reads F0 < 0.02 as baked specular occlusion). Keep every other foliage map's ORM.G and slot roughness below 0.95.
- **A self-union of overlapping bark tubes does not fit a tree budget.** The EXACT Boolean self-union removes every buried receiver face but took the oak's bark from 1,144 to 2,254 tris (the intersection seams); the MANIFOLD solver does not self-union (empty operand: no change). Trimming a branch's buried start fails when the branch is thicker than the trunk strand it leaves (oak roots r 0.7 vs strands r 0.45: no ring is ever fully buried). Report AO over visible texels (`_oak.hidden_texels`) instead.
- **High-poly fissure relief is noise in a coarse AO bake.** When a tileable set carries the bark's colour, normal and fissure AO, the high poly feeds only the macro AO (masks.A, 59 px/m on the oak). Its 0.07 m ridges did not line up with the set's fissures and baked as uncorrelated dark streaks; 0.025 m raised the oak's visible bark AO from 0.721 to 0.758 with the strand grooves and junctions still dark (`live/07_p3_bark_relief.py`).
- **Do not transfer UVs from LOD0 to rebuilt LODs by nearest face.** A `DATA_TRANSFER` (`POLYINTERP_NEAREST`) gives LOD faces whose corners touch two LOD0 islands UVs from both, so they stretch across the atlas and sample garbage (house_cottage: LOD1 glass lost its night glow). Unwrap all LODs into one atlas and bake each LOD onto its own islands (`clear` on the first bake only, margin below the island spacing), as `kit/_house.py` does. Verify per LOD on the reimported GLB: density min, median and max, plus the masks value at key faces. The 6-view render shows only LOD0.
- **LOD seams.** `VisibilityRange` applies per chunk, so neighbouring tiles can sit at different LODs. Pin the border ring in every LOD and choose its subdivision so LOD2 can still reach 15%.

- **A lathed prop can share UV islands across its repeats.** Map each repeat of a rotationally repeated prop (a round bale's four barrel quarters, both end caps) onto one shared island with UVs computed from the profile, and every LOD samples LOD0's atlas exactly with no decimation. Bake onto a receiver that keeps one copy of each island, the top one, so ground-contact AO stays off it (`_hay.py`).
- **Cull a stacked prop's hidden faces against the neighbours' real surfaces.** An inflated-box test removed the bevels between bales and opened see-through slits; a ray test against each neighbour's actual mesh keeps them (`_hay.py`, 2026-10-19).
- **A lane-less centre piece is kind `prop`.** `kit_gate::check_center_edge_joint` treats every `center` without `socket-lane-*` nodes as the road hub, which must have sections at x = ±6 matching the edge pieces. Tile detail with no lanes (ocean_center's pebbles and rocks) fails that, so it ships as kind `prop` (LOD0 ≤ 1,500 tris, no border or joint checks), still named in the tile's `center` field.
- **A thin multi-part prop keeps its posts at every LOD.** `fence_paddock`'s first LOD2 dropped every post and kept two 0.1 m rails, so the paddock read as gone past 400 m; keeping every other post (corners and gate posts always) fits the 15% ceiling. Check such LODs with Force LOD 2 at play distance.
- **A coarse LOD that samples LOD0's baked tangent map needs LOD0's normals where it can take them.** The bake writes the high's normal relative to LOD0's interpolated normal, so a LOD built per island with few columns (one quad per 60-degree apron segment) reads the map in a tilted frame that differs across each seam (`hay_bale_round_b`, a 36 degree step). Where a LOD's vertices coincide with LOD0's, copy LOD0's normal per island as a custom normal (`_hay_var.apron_normals_from_lod0`) and check it in the GLB. A shared repeat island (four barrel sectors on one UV island) also needs its procedural content to repeat per sector and a bake surface carrying the full mesh's normals (`_hay.periodic_point`, `receiver_of`).

## Coordinate frame and export
- Blender Z-up exports to glTF Y-up as glTF x = Blender x and glTF z = −Blender y. Runtime edge 0 faces +x, edges run clockwise viewed from +Y, and +z is south. In Blender's top view, edge k's outward normal is at −60°·k.
- Use a hex-center pivot for every piece. Author edge pieces for edge 0 and rotate them at runtime (PRD §6).
- Apply transforms before joining. Check the result with root-relative positions on reimport, not in the viewport.
- Each parentless root becomes one GLB in multi-root exports, so use one root per piece. `export_extras=True` carries socket metadata.
- Hidden-from-render objects can drop out of selected exports. Keep the collider render-visible during export and hide it in the engine.
- Export no images: textures are separate files.
- **`assets/kit/manifest.json` is hand-formatted.** A `json.dump` round trip reflows it into about 2,000 changed lines. Insert a new piece's entry as text (copy the original's block by brace depth and swap the id, `prop-variants` 2026-10-14), then parse the file to check it.
- **Keep attributes FLOAT.** bevy_gltf 0.20 rejects `KHR_mesh_quantization`. If a later phase quantizes, it needs dequantization in `meshopt_glb.rs` and one shared quantization volume (the hex bounds): per-mesh bounds snap neighbouring border vertices to different grids and the seams crack.
- **Imported glTF objects use quaternion rotation.** Setting `rotation_euler` on an imported root does nothing until `rotation_mode = "XYZ"` (self-review composites that place edge stubs at other edges).
- **The glTF exporter flips V.** A UV map exports as 1 − v (harmless for cyclic data such as wind phase).
- **Colour attributes never export as FLOAT.** Blender 5.2 writes a colour attribute as normalized UNSIGNED_SHORT, and with `export_all_vertex_colors` (on by default) adds a fake white UNSIGNED_BYTE COLOR_0, pushing the real one to COLOR_1. D7 rejects both. A piece that needs COLOR_0 (the cars' paint mask, PRD §6 runtime recolour) rewrites the exported GLB before the export report: `kit/_car.py` `float_color0` makes the authored attribute COLOR_0 FLOAT VEC4, drops the other COLOR_n and repacks the BIN. StandardMaterial multiplies COLOR_0 into base colour, so author rgb as the surface colour (white where a runtime tint applies).
- **Triangulate n-gons before export.** The exporter cannot compute tangents on n-gons (loft caps, wheel hubs) and drops TANGENT with only a warning; `kit_gate` then fails the piece. Triangulate every LOD before the unwrap and bake.

## Turning road pieces (bends, junctions)
- **Stubs fix the joint at r = 6.** A road tile places `road_straight_edge` at every lane edge, so a turning centre piece meets a straight stub at r = 6 on each lane ray. A bend is then an arc tangent to both rays there, radius 6·tan(α/2) for lane rays α apart: 10.392 m (lanes 0 and 2) and 3.464 m (lanes 0 and 1). The 3.464 m arc is tighter than the profile's half width (SINK_T 4.6), so the inner verge cannot be swept on the bend side; `_road_bend.py` stops the sweep at the kerb foot and sweeps the dropped verge points round the far side of the arc centre. On `road_bend_60` that far-side fan lay entirely under both stubs, so the tile now places two trimmed stubs (`road_bend_60_edge_e0`/`_e1`, `_road_bend_trim.py`) and its centre drops the far-side rows (owner A7, 2026-10-25).
- **Cutting a swept piece with `bisect_plane`: keep rows away from the cut.** Where the cut crosses each profile line, check the nearest row in every LOD (the 60-degree trim meets t = -4 at x = 6.928 and t = -4.6 at x = 7.967; road_straight_edge's LOD1 row at 7.964 would leave a 3 mm sliver), pick segment counts that keep them centimetres apart, and assert a minimum triangle area after the cut (`_road_bend_trim.MIN_TRI_AREA`).
- **A mirrored pair of cut pieces: mirror the mesh, not the cut.** `_road.build` splits every cell along the same diagonal, so its -y half is not the +y half mirrored; cut one piece and build its partner by mirroring the cut mesh (y -> -y, `bmesh.ops.reverse_faces`), so both meet vertex for vertex on the cut (`_road_bend_trim.trim`). The mirrored piece's 64-sample AO bake then differs at noise level (up to 20 levels on about 1% of texels).
- **The `_road.py` bend dash rule meets frozen stubs.** The stubs keep period P with a dash crossing the joint (on for 1.843 m inside the centre piece), so a centre path starts and ends with that dash and spreads the rest evenly (`_road_bend.dash_intervals`).
- **Never edit `_road.py` for a new road piece.** It is a hashed `generatorDep` of every piece that imports it directly or through another family file (the road pieces, both pads, both river bridges and the rail crossing; list them with `grep -l _road scripts/blender/kit/*.py`), so an edit means rebuilding and re-approving all of them; shared turning code lives in `_road_bend.py`, which imports it.
- **The kit scenario spawns no water.** A river piece placed there shows a dry channel; shoot water, fish and reflections in play once the piece has a tile.
- **A ground slope that should read as ground needs up normals.** The verge sink is a 31-degree slope that dives under the meadow cap, and with its true normal the side facing away from the sun read at about half the meadow's luminance in play, a dark strip between the kerb and the line where the cap relief cuts it (owner bug, 2026-10-14). `_road.verge_normals_up` gives every road_verge loop a +Z custom normal after the last join and `set_sharp_from_angle` (both rebuild corner normals). A flat-shaded face ignores custom normals, so make those faces smooth first. Normals survive `kit-compress`; check the compressed GLB, not only the staged one.
- **Re-shoot an old visual card at HEAD before fixing it.** A look card can be fixed by a later change to a shared helper: the 60-degree bend's inner-corner "crease" (filed 2026-10-13) was the verge sink shading that `verge_normals_up` fixed a day later. Shoot the card's view at HEAD first. For the before side, rebuild the filed state from the git GLBs in a scratch `assets/` copy (`git archive <rev> <glb>...`) and run the binary or `scripts/shots/piece.py` with that copy as the working directory; swap one GLB at a time to find the piece that carries the defect (`docs/checkpoints/road_bend_60-crease/prefix.sh`). Native runs have no asset-root flag, so `make shots-piece` cannot do this from the repo root.
- **Check the joint in the generator.** `_road_bend.joint_section_errors` mirrors the gate's per-lane section test on the built LODs, so a stray vertex on a joint plane fails the build, not the later `kit-check`.

## Water beds (river and coast families)
- **A coast bed's ring is not flat, and the lib's border helpers assume it is.** `geom.cdt_cap`, `geom.set_border_normals_up` and `lod.border_verts` / `assert_border_identical` all filter on z = 0. A beach base's ring follows the profile on its beach edges, so `_beach.py` builds its own constrained-Delaunay cap, compares rings on full (x, y, z) and sets analytic normals (n = normalize(-h'(s) grad s, 1); on a beach edge grad s runs along the edge on all three tiles, so a seam shades alike).
- **Build a coast bed from rows of constant s.** Every iso-s line with |s| < 8 crosses the border only on the two beach edges, at the point s m from the edge midpoint toward the sea corner, so one shared list of rows serves the straight beach (lines) and both corner tiles (arcs about C, which lies on both beach-edge lines). The rows end on ring points and stay the same in every LOD. The 1 m ring lattice misses the smoothstep drop by 0.054 m, so the beach edges carry extra samples at 3.5-7.5 (and the damp band's top), the same on every coast base (`kit_gate::check_coast_seams`). On the arcs, spend LOD2 triangles on the drop rows (chord sag x slope must stay under what the row spacing leaves of 0.03 m); the corner tiles need the 20% LOD2 ceiling (`kit_gate` `COAST_ARC_LOD2_MAX_RATIO`).
- **A tileable slot cannot be glossier.** `kit_material.wesl` replaces a tileable slot's roughness with the set's ORM.G, so the manifest `roughness` has no effect there. A wet band is a darker slot tint of the same set (`beach_wet`), on its own rows. The live swash band at the waterline (gloss and the soaked line) comes from the shader, not the bake: set `wetBand` on the slot in the manifest (water contract §3).
- **The bed profile is a requirement, not a look.** The engine computes every water input from the analytic profiles in `docs/kit/water-contract.md` and never reads the bed mesh, so sample the built bed against the profile in the generator (vertices and face centroids; 0.03 m where the water is under 2.5 m deep, 0.10 m elsewhere) and keep the dry cap relief within 0.10 m (`_river.profile_errors`, `RELIEF`). The tolerance binds every LOD (the engine draws depth and foam from the profile whatever LOD the bed shows). Build the channel as a structured strip whose every vertex carries the exact profile, and sample the profile's kinks: linear interpolation across the bed's kink at d = w misses it by 0.027 m at 0.49 m spacing, and a curved channel adds chord sag (about slope x rho x dtheta^2 / 8), so the 24 m bend needs 16 radial rows even at LOD2. Spend LOD2 triangles on rows, thinning the lateral offsets instead (`river_bend_base.py`).
- **A long straight stub cannot meet a contract arc.** The river bend is fixed on the 24 m arc, which leaves a straight stub of length L by L^2 / 48 at its inner end. `river_edge` is 1 m long (0.021 m) and the channel-cut bases own the rest of the channel, with a notch where the stub sits.
- **A river tile needs a lane-cut base, not `meadow_base`.** A full meadow cap buries the channel, and a base whose ring leaves out the channel cannot map onto itself under 60 degrees. A base declares its cut lanes as `socket-lane-*` nodes with `kind` and a `cut` half-width; the gate then checks its ring against the lattice outside the cuts and its joint with the edge piece (`gates.md`, Seam: lanes and border ring).
- **A water tile's kit bed follows its base piece, not its centre.** The engine draws the kit bed as soon as the tile's `base` piece is in the kit (`water::tiles::stand_in_bed`); the centre only gates the river lane strips (`play.rs`, `pending_water`). A water tile may have no centre at all: the river channels, mouths, beach and ocean tiles carry `center: None` since 2026-10-26, their dressing being scatter. Tests that assume every water tile has a centre fail then (the stand-in bed test did).
- **A scatter prop on a water bed is part of the bed the water reads.** Size its top against the bed's allowance at the scatter's largest scale (up to 1.15) and stand it at the contract level, not on the relief (`scatter::SEABED_Y`, `_stones.TOP_MAX_SEABED`).
- **A scatter prop for sloping ground is laid out along one axis.** `scatter::stand` seats a piece at the lowest height under its centre and a 0.3 m ring, so a round cluster on a bank floats on its downhill side. String the cluster along +x and let the scatter lay +x along the slope's contour at the centre's height (`contour`, river bank props).
- **Split shared helpers by who imports them.** Provenance hashes every imported `_*.py`, so code only the later pieces need (`_river_dress.py`, `_river_bridge.py`) lives apart from the helper the gated base and stub import (`_river.py`); otherwise every edit marks them stale (a `make kit-check` warning and a rebuild to schedule, since 2026-10-19 no longer a failure).
- **A min() bed has a crease; trace it in the coordinate where one term is constant.** The river mouth's bed is min(coast(s), channel(d, s)) (`_mouth_profile.py`). Lines of constant x miss part of the in-channel region and join the crease to the tip with a long chord that refinement cannot fix; along iso-s rows the in-channel set is one interval about the centre line. Put vertices on the crease and give each face's loops the normal of its own side (`_mouth.py`), or the top render shows a sawtooth along it.
- **Water-bed LOD2 floors are higher than the PLAN tables assume.** Every LOD carries the 0.03 m tolerance, so a lane-cut base with a fan or a pool needs about 700 LOD2 tris (`river_mouth_base` 715 of 3,600 with its grass line, `river_spring_base` 726 of 3,970): the notched ring and skirt fix about 200-260, and the crease or the pool's kink rings (chord sag about slope × r × dθ² / 8) the rest. Size LOD0 near the 4,000 cap so LOD2 fits the 20% lane-cut ceiling. Refine by splitting the longest non-ring edge against the bed only (refining against relief never ends); constraint lines at fixed d / w(s) give long triangles along a channel and beat isotropic Delaunay refinement by about a third.
- **A hull collider over a constant-UV skirt can carry zero tangents.** gltf-validator then fails `kit-compress` with ACCESSOR_VECTOR3_NON_UNIT. Dissolve degenerate hull faces, flat-shade the collider and give it an oblique planar UV; also drop cap points within about 3 cm of another point or constraint, which leave slivers with zero tangents.
- **Prove an unchanged mesh on the compressed GLB.** Hash `assets/kit/p1/<id>/<id>.glb` before the rebuild and again after `kit-compress`. The staged GLB in `target/kit-stage/` is Blender's uncompressed export and never equals the committed file (a texture-only rebuild, 2026-10-26).
- **Check the exported GLB at the gate's sample density**, not only the in-memory cap: re-sample the compressed LODs the way `kit_gate` does (4 subdivisions per face edge) before calling a water bed done.
- **Slots cannot blend; a colour step between sets needs COLOR_0, not a tint.** The river mouth's gravel bed met plaster sand along the crease as a crisp line (owner, 2026-10-14). Tinting gravel up to the sand's mean puts its stones over albedo 1 (linear std 0.13 against plaster's 0.03), so join like sets where the line runs (gravel bed to gravel seabed under the water, plaster banks to plaster sand above it) and write COLOR_0 FLOAT VEC4 straight into the exported GLB per primitive (`_mouth.add_color0`; Blender's colour export is normalized and clamps): rgb scales the slot tint toward one target field, a is the detail weight that `kit_material.wesl` uses to fade the set to its top-mip mean, its relief and the live wet band. Keep rgb in [0, 1] by raising the slot tint in the manifest, and assert border and joint vertices keep their neighbours' look.
- **A slot edge on a CDT cap is a constraint, not a height test.** Slots assigned by face centre against a contour that is not a constrained row follow triangle edges: the river mouth's grass line (GRASS_Z on a channel that widens) was a sawtooth, with a notch where the slot rule switched at s = -8 (owner, 2026-10-14). Put the edge on a constraint polyline in every LOD (`_mouth.grass_lines`, on `river_straight`'s grass row so the joint meets `river_edge` vertex for vertex). Classify faces by the side of that LOD's own polyline, not the exact curve, because a face inside the chord sag flips. End the polyline on existing vertices where other constraints cross it (the fillet ends on a q-line vertex), and use one slot rule on both sides of a profile seam.
- **Set material slots before material indices.** `polygon.material_index` is clamped to the mesh's slot count when assigned, so an index set before `materials.append` silently becomes 0 and the whole piece exports as one primitive. Indices written through bmesh survive `to_mesh`. Check the exported primitives' material names.
- **bmesh refuses a back face on the same vertices.** Give each side of a double-sided card its own vertices.
- **Adding a bmesh custom-data layer invalidates every BMVert reference you hold.** `bm.verts.layers.float.new(...)` after creating vertices raises `ReferenceError: BMesh data of type BMVert has been removed` on the next write to a held vertex (the plant wind layers, 2026-10-14). Create the layers before the first vertex of the part (`_river_dress.wind_layers(bm)` at the top of `_reed_clump`). Vertex float layers become POINT attributes on `to_mesh`, and `geom.join` fills them with 0 on parts that lack them.

## KTX2
- KTX-Software 4.4.2 `ktx create --encode` accepts only `basis-lz` or `uastc`, so BC7 is reachable only by transcoding (`ktx transcode --target bc7`). The pipeline encodes one UASTC q4 source (RDO, zstd 18) and transcodes it to BC7 and ASTC, so both families carry identical content. Encode ASTC directly only if a measured PSNR shortfall demands it.
- Normals may use `--target bc5` (two channels). Bevy's two-component normal reconstruction for BC5 is unverified here.
- Mips: albedo must be averaged in linear light and normals renormalized at each level (external vault packing note).
- UASTC RDO barely helps size. Detailed 1024² maps land at 0.90-1.25 B per base pixel including mips, against a raw 1.33, so resolution is the only real budget lever (`docs/perf/p1-texture-budget-probe.md`).
- PNG input carries no transfer function. `ktx create --format R8G8B8A8_UNORM` without `--assign-tf linear` assumes sRGB and silently applies a lossy sRGB-to-linear conversion. `encodeMap` always passes `--assign-tf`, and `--normalize` is rejected for sRGB formats. The runtime decides a PNG's colour space from the channel name.

## Look-dev and engine shots
- **Look-dev parity.** Blender's view transform does not match Bevy's tonemapper. The 6-view Blender renders are evidence only; approval happens in engine.
- **The 6-view render is untextured.** The GLB embeds no images, so alpha cards render as solid quads and a tileable slot as its flat colour. Judge foliage from a headless EEVEE still that binds the staged maps (alpha clip, the set at the slot's `tileUvScale` and tint), then in engine.
- **The 6-view render is untextured.** `make kit-renders` imports the GLB, which embeds no images, so it shows geometry and shading only. Judge a unique bake from a still with the stage PNGs bound (albedo × ORM.R, ORM.G roughness, the normal map), rendered headless with EEVEE, before compressing.
- **Kit-scenario props need a height.** `finish_kit` places a piece at the cell's y = 0, but the meadow cap's relief dips to −0.25 m, so a prop placed at 0 floats. `Placement.y` carries the relief height at the prop's spot (`relief()` in `meadow_base.py`, evaluated at the offset rotated by the prop's own k, in Blender coordinates x, −z).
- **A white face turned away from the kit sun reads dark slate in engine.** It gets sky light only and measures about 20-35 brightness, the same as the approved `house_twostorey`'s north wall (22). Quote that comparison on the review sheet instead of re-tinting the asset (crossing gates, 2026-10-19).
- **Shadow acne in an in-engine shot is a renderer issue first.** Grazing-angle kerb walls showed sawtooth acne that a `--shadows off` shot removed entirely; the fix was in the kit's shadow settings, not the asset.
- **Before judging a dark wall in engine, shoot it beside a yaw-0 piece with `--shadows off`.** A face turned away from the sun can't read brighter than one facing it; if a yawed piece's sun-facing wall is dark next to a lit yaw-0 wall, suspect the renderer, not the asset (2026-10-19: yawed cottages, bakery and barn rendered unlit walls, card `01a155602a2f`). The binary has no `--help` (it launches the app); every flag is in `docs/agent-operability.md`.
- **Place review pieces in open sun.** The kit sun sits at (200, 400, 150), so a tall neighbour's shadow falls toward its -x/-z side; the first hay stack spot sat in the oak's shadow and read as dark (2026-10-19).
- **Native shots can come back black.** A screenshot taken right before `exit` in a `--script` was written all black (the capture lands after teardown starts), and whole runs wrote every shot black while the display was idle-asleep (macOS stops presenting the window). End shot scripts with a `wait` after the last `screenshot`, run the shots under `caffeinate -u -d -t 600`, and check each PNG's mean (`magick f.png -format '%[fx:mean]' info:`) before reading it; re-run a run whose shots read 0. An idle display also fakes a bisect: river-family black frames seemed to follow rotation, `--shadows`, one manifest entry and one material slot, and were all the display. They also came and went between back-to-back runs of one binary under `caffeinate -u -d` (host load 40-110), so re-run the identical run before blaming an asset. A window fully covered by another app's window also captures all black, at any load: on 2026-10-14 every `make thumbs` capture was black while its 384 px window sat under the frontmost terminal (the macOS window list showed it there), and the same runs rendered once the window floated. `--thumbs` now opens its window always on top; keep other small-window native runs uncovered.
- **Tileable layers are sampled in world space** (`kit_material.wesl`), so neighbours line up under rotation. The exception is a slot with `tileUvScale` (tree bark), which samples its set on UV0 (`project.md`).
- **When native window shots stay black, use the offscreen photo export or the web build.** On 2026-10-20 three agents got all-black window captures on every retry at host load 300-470 (covered windows). The game's offscreen `photo_export` (docs/agent-operability.md) rendered the same frames (`docs/checkpoints/fence-lod2/run.py`); before-and-after pairs shot on one web build in headless GPU Chromium, with the LOD forced inside the script, also work (`docs/checkpoints/hay-bale-seams/run-web.sh`). A stalled fixed-clock run resumes once its window is brought to the front. Forced LOD shots move the ground's LOD too, so a thin draped part (a straw apron, a verge) can sink under a LOD2 base: for seam evidence on such a part render the LOD alone in a textured EEVEE still.

## Higgsfield references
- **Never edit `scripts/refs/higgsfield-refs.sh` while a `make refs` run is in flight.** Bash reads the script from disk as it runs, so an in-place edit kills the run with a syntax error, usually after the images download and before `refs.json` is written (P2 wave 1: ocean, meadow_props, river_road_bridge, house_cluster). Recovery is free: completed `job-N.json` files are cached, so re-running `make refs PIECE=<id>` re-downloads and writes `refs.json` with no new generation. Make every edit first, run `bash -n`, then launch. To force a new image for one slot, delete that slot's `job-N.json` first.
- **Moderation rejects some harmless wording at submit time and refunds the credits.** The job returns `nsfw` or `failed` within about 5 s, the status can differ between identical submissions, and resubmitting the same prompt does not help; rewording does. Rejected in P2: "enters … bed … deep" (river), "young slender" (forest), "glossy wet … sand bed" (beach). Passed: "runs from", "channel floor", "damp-sand band", "sandy floor". Rejected for river_mouth ref-3: "clear fresh water … spreads into a wide shallow fan … the fresh water meets a … surf foam line breaking gently"; passed: "a small clear river runs from … opening out into a broad shallow stream … runs into the sea at a lacy white surf foam line". Rejected for water_props ref-4 (B3): "in the slack water on the inside of the bend … grows out of the shallows"; passed: "on the calm water close to the inner bank … stands … its stems rising from the water". Check `higgsfield --json account transactions` for the refund to tell moderation from a backend failure.
- **The model will not hold multi-tile layouts or adjacent-edge geometry.** Three-tile prompts drift (hairpins, T for Y), so prompt one tile per image with a high camera (about 65°). A sharp 60° bend (road ends on adjacent hex sides) failed three wordings; references fix the look, and the bend geometry comes from the `_road.py` lane contract, so a reference with the wrong angle is still usable for the look.
- **Negative clauses do not stop emblems.** A shared "no logos or emblems" clause still produced grille badges on cars; a positive description in the slot's own prompt worked ("a plain grille of smooth horizontal slats with a blank centre and no emblem"). Reword only the failing slot's prompt, never a shared variable, or refs.json pairs the new prompt text with an old cached image.
- **A fresh worktree has no `scripts/assets/node_modules`.** `make refs` and `contact-sheet.mjs` fail until `cd scripts/assets && npm ci` runs there. Nor does it have `tools/ktx-4.4.2` (gitignored), which `make kit-compress` needs: `./scripts/worktree-bootstrap.sh` sets up both (and the rest of the worktree) in one command.
- **Frame-filling scenes drop the studio-background clause.** A top-down fish school with "neutral grey studio background" came back as a square resin block of water on a grey table, and birds "flying in mid-air" over a meadow came back on visible support stakes over a small square moss fragment, larger than the trees. Write the scene as running "out past every edge of the frame", birds as "flying freely through open air", and leave out "neutral grey studio background" in those slots only (fish and birds ref-2, P2).
- **"Looking straight down from directly above" is not enough for an overhead view.** It gave a high-oblique, golden-hour shot of birds over a hazy landscape. "A bird's-eye view photographed from directly overhead with the camera pointing straight down at the ground", with "a flat map-like landscape far below" and "bright midday light", gave a true overhead view at noon (birds ref-2).
- **Naming the variants prints labels.** "Two small fish … for a colour comparison … an ocean fish … a river fish" printed OCEAN and RIVER beside them. Describe only each one's colours ("the upper fish is coloured with …") and end with "the picture shows only the two fish on the plain backdrop" (fish ref-3).
- **A 503 during `--wait` can strand a job that was already created and charged.** With seven `make refs` runs in parallel, one failed with `Higgsfield API error (HTTP 503)` and left `job-1.json` holding `[]`, yet the transaction log showed the spend and the job finished. Do not resubmit. Find it with `higgsfield --json generate list` (match the prompt and time), write `higgsfield --json generate get <id>` into that slot's `job-N.json`, and re-run `make refs`: the cache check accepts it and nothing new is charged (P3 rail_station ref-1).
- **A number in a single-object prompt can print a scale bar.** "A single sheep about 0.8 m tall at the shoulder" came back with a ruler labelled 0.8m beside it; the cow slot with "about 1.5 m" did not, so it is random. Leave sizes out of studio single-object slots and end them with "the picture shows only the sheep on the plain backdrop" (farm_animals ref-2, P3).
- **"Exactly side-on in true side profile" does not hold for a long object.** It gave a three-quarter view of a three-vehicle train. "An exact side elevation … the camera looks at the middle of the train at a perfect right angle to the track from far away through a long telephoto lens, level with the wheel axles, so … no front or end faces are visible" gave a true elevation (train ref-2, P3).
- **"A low rounded grassy mound" is ignored on a hex tile; the tile comes back flat.** "The whole grass cap swells up into one broad smooth grassy hill that rises from the tile edges to a rounded top about 4 m higher in the middle, like an upturned saucer" with the building "on the very top of the hill" worked (windmill ref-3, P3).
